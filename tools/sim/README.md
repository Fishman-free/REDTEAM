# P0 机制参数仿真（tools/sim）

对应规格：`docs/superpowers/specs/2026-10-27-rtm-redteam-game-design.md` §1.1 / §3.5 / §10。
对应计划：`docs/superpowers/plans/2026-10-27-rtm-redteam-game-plan-a.md` 任务 2。

实现：`tools/sim/mechanism_sim.py`。纯 Python 标准库，确定性，无随机数、无网络、无外部依赖。

**结论先行：**

- 奖池只含守方质押，罚款与奖金是参与方之间的转移，因此对称信息下攻守双方**不可能同时为正 EV**。
- 强守方（真实攻破概率 `p_def < p_market`）可以在市场低估窗口获得正 EV；这是信息不对称的租金，随声誉收敛而收窄，最终归零。
- **对称情形守方 EV < 0 是机制事实，不是实现缺陷。**
- **本 P0 仿真只覆盖用户攻防层**；平台挖矿层是固定 1 RTM/成功攻破的事件驱动发行，不参与本模型的 N*、罚没曲线或零和恒等式。

## 1. 运行

```bash
python tools/sim/mechanism_sim.py
```

覆盖扫描与成本参数：

```bash
# 扩大 p_market 扫描
python tools/sim/mechanism_sim.py --p-market 0.005 0.009 0.0092 0.01 0.02 0.025 0.05 0.1

# 变化消息数 / 推理成本 / 手续费
python tools/sim/mechanism_sim.py --M 36
python tools/sim/mechanism_sim.py --llm-cost 0.04
python tools/sim/mechanism_sim.py --fee-rate 0.0025
```

CLI 参数：

| 参数 | 默认值 | 作用 |
|---|---:|---|
| `--p-market` | `0.005 0.01 0.02 0.05` | 市场预期的单条消息攻破概率扫描 |
| `--M` | `72` | 每名攻方全程消息数（默认 24h × 3 条/小时） |
| `--llm-cost` | `0.02` | 每条消息的攻方推理成本（RTM） |
| `--fee-rate` | `0.005` | 消息费占 S 的比例（默认 0.5%，即 0.25 RTM/条） |
| `--decay` | `1.0` | 单条攻破概率随轮次的衰减；`<1` 表示比赛内防御逐渐变强 |
| `--strong-fraction` | `0.5` | 强守方 `ratio = 阈值 × 该比例` |

固定参数（与规格 §3.2 一致）：`S=50`、`r=0.10`（`s=5`）、`K=12`（24h / 2h）、`keep=0.75`、攻方人数上限 50。

输入边界：所有数值参数必须有限（`math.isfinite`，拒绝 NaN/Inf）；且 `fee_rate·S + llm_cost > 0`。零成本配置不属于模型范围，`validate()` 会以 `ValueError` 退出。

输出为 NDJSON：每行一个 JSON 对象（`params`、`self_play`、每个 `p_market` 一行 `market`、一行 `assertions`），最后一行以 `OK:` 开头。全部断言通过时退出码为 0；失败时输出断言明细后抛 `AssertionError`，退出码非 0。

**N*=0 行：** 该 `p_market` 下没有攻方入场。`N_star=0`、`attacker_ev_expected=null`、强守方相关字段（`threshold_ratio`、`strong_ratio`、`p_def`、`attacker_ev_realized`、`defender_ev_strong`）均为 `null`，守方 EV 为 0，零和残差为 0。额外字段 `attacker_ev_first_entrant` / `attacker_ev_next_entrant` 给出第一个入场者的 EV，用于解释为何无人入场。默认扫描中的 `p_market=0.005` 就是这种情况，脚本不会报错。

## 2. 模型假设与公式

### 2.1 默认参数

| 符号 | 默认值 | 依据 / 说明 |
|---|---:|---|
| `S` | 50 RTM | 守方质押，也是奖池；规格 §3.2 |
| `r` | 0.10 | 攻方质押比例，`s = r·S = 5`；规格 §3.2 的范围 [2%, 20%] |
| `D` / `E` / `K` | 24h / 2h / 12 | 比赛时长 / 罚款周期 / 全程 epoch 数 |
| `keep` | 0.75 | 每 epoch 保留剩余质押的 75%（罚 25%）；`keep^K ≈ 0.031676` |
| `F` | 4.841618 RTM | 全程持有近似下每名攻方的罚没 `s·(1−keep^K)` |
| `fee_rate` | 0.005 | 消息费占 S 的比例，`fee = 0.25 RTM/条` |
| `M` | 72 | 每攻方 24h × 3 条/小时的**工作负载假设** |
| `llm_cost` | 0.02 RTM/条 | **工程占位值**，需用实际模型/供应商账单替换 |
| `c` | 0.27 RTM/条 | `fee_rate·S + llm_cost`，必须 >0；零成本配置直接报错 |
| `M·c` | 19.44 RTM | 每名攻方全程消息成本；`F + M·c = 24.281618` |
| 攻方人数上限 | 50 | 规格的 gas / 状态上界 |
| `strong_fraction` | 0.5 | 仅用于展示强守方场景，取强度阈值的一半 |

`M` 和 `llm_cost` 不是链上定值，而是 P0 的工作负载假设；第 5 节给出敏感性。主网上线前应以真实 runner 吞吐和模型账单替换。

### 2.2 `p_market` 与 `p_def`：信息不对称

- `p_market`：攻方在**入场时**对"该守方单条消息会被攻破"的市场平均预期。攻方据此决定是否加入，N* 由 `p_market` 计算。
- `p_def`：守方的**真实**单条消息攻破概率。比赛结算和守方 EV 用 `p_def`。
- 强守方：`p_def < p_market`。市场低估了守方，攻方按偏乐观的预期入场，实际胜率更低；守方获得正 EV。
- 弱守方：`p_def > p_market`。守方 EV 更差，长期会亏损并退出。
- 排行榜、存活记录和历史攻破率让 `p_market` 逐步向 `p_def` 收敛。

这不是"双方同时正 EV"的机制；机制靠**技能分化**和**信息不对称**运转。

### 2.3 概率模型

每轮 `m = 1..M`，`N` 名攻方各发一条消息。单条消息攻破概率：

```
p_m = p × decay^(m-1)
```

其中 `p` 在计算 N* 和市场 EV 时取 `p_market`，在计算真实结果和守方 EV 时取 `p_def`。默认 `decay=1.0`，即每条消息独立同分布；`decay<1` 可模拟比赛内防御随消息增加而变强。

第 `m` 轮开始前的生存率（此前所有轮次无人攻破）：

```
surv_m = Π_{j=1}^{m-1} (1 - p_j)^N
```

单个攻方的总胜率：

```
p_self = Σ_{m=1}^{M} surv_m × (1 - (1 - p_m)^N) / N
```

守方全程存活率：

```
P_survive = Π_{m=1}^{M} (1 - p_m)^N
```

**顺序必须正确：** 先使用本轮之前的 `surv_m` 累加 `p_self`，再把本轮 N 人全部失败的概率 `(1−p_m)^N` 并入生存率。若先更新 `p_any` 再累加，会低估攻方胜率，得到错误的 N*。实现中 `surv_m` 在循环顶部使用，循环末尾才更新。

同轮多人同时攻破时，胜者在同时攻破者中均匀产生；由对称性，单攻方在该轮的获胜概率正是 `(1−(1−p_m)^N)/N`。于是有精确的 telescoping 关系：

```
N × p_self = 1 - P_survive
```

脚本内置 `self_check()`，对 `p ∈ {0.001, 0.005, 0.01, 0.05, 0.2}`、`N ∈ {1,2,5}`、`decay ∈ {1.0,0.99}` 共 30 组检查 `|N·p_self − (1−P_survive)| < 1e-12`。`self_check()` 还对**当前扫描**去重后的 `N*>0` 市场比较闭式阈值与二分结果，并在默认参数 + 默认扫描时执行 4 项 golden 回归。全部结果写入 `assertions` 的 `analytical_self_checks` 项，失败时非零退出。

### 2.4 收益公式

```
F = s × (1 - keep^K)                                   # 全程罚没（每名攻方）
EV_att(p, N) = p_self × S - F - M × (fee_rate×S + llm_cost)
             = p_self × S - F - M × c
EV_def(p, N) = N × F + S × P_survive(p, N) - S
EV_selfplay  = -M × c                                  # 罚款/奖金是内部转移
```

攻方 EV 的原始形式是 `p_self×S + s×keep^K − s − M×c`，其中 `s×keep^K − s = −F`。**无论胜负，未罚没的剩余质押 `s×keep^K` 均可取回；获胜者额外获得 `S`**（奖金与质押返还并存）。全程消息成本是 `M·c`。

守方 EV 的直观含义：若守住，取回 `S`；若被攻破，失去 `S`；无论结果都按全程近似收取 `N·F` 的攻方罚没。

### 2.5 "全程持有"近似及其偏差方向

本仿真采用**全程持有**近似：

- 每名攻方都被按全程 `K` 个 epoch 计罚 `F`，并支付全部 `M` 条消息成本；
- 守方在所有路径上都被记入 `N·F` 的罚没收入。

真实比赛中，一旦有人提前攻破，比赛立即结束，所有攻方停止继续被罚、也不再发消息。因此：

- **无人攻破路径**（概率 `P_survive`）：近似与真实完全一致。
- **提前攻破路径**（概率 `1−P_survive`）：近似**高估攻方成本 / 低估攻方真实 EV**，同时**高估守方罚没收入 / 高估守方 EV**。

也就是说，强守方的正 EV 在本模型中是一个**上界**，而不是精确值。强守方的 `P_survive` 很高（默认强守方示例：`p_market=0.01, N=1` 时约 `0.950368`，`p_market=0.05, N=2` 时约 `0.897998`；这两个数由公式 `P_survive=(1−p_def)^{N·M}` 计算，**不是脚本输出字段**），偏差主要来自少数提前攻破路径，量级有限；但主网参数定稿前仍应做**路径级**仿真（按首次攻破时间结算），不能只依赖本近似。同时，攻方 EV 被低估意味着 `N*` 也可能偏保守（真实入场人数可能更多）；强守方 EV 的上界只在给定 `N*` 下成立，路径级模型需要联合重算 `N*` 和守方 EV。

未建模的因素还包括：攻方异质性/技能分布、风险偏好、资金时间价值、守方推理成本、数据市场收入、声誉价值、RTM 法币价格、挖矿层固定 1 RTM/成功攻破的事件驱动记账（P5 单独验证）、链上 gas（测试网零 gas）。这些都需要在 P1/P5 参数定稿前复核。

### 2.6 N*、阈值与强守方场景

`N*`：按 `p_market` 计算单攻方 EV，取满足 `EV_att(p_market, N) ≥ 0` 的**最大整数 N**，上限 50；若 `N=1` 仍为负，则 `N*=0`，无攻方入场，守方 EV=0。由于 `p_self = (1−q^N)/N`，其中 `q = Π_m (1−p_m)` 是单个攻方全程都不攻破的概率，`P_survive = q^N`，单攻方 EV 随 N 递减，因此最大 N 是良定义的。若 `N*=50`，断言只验证 `EV_att(p,50) ≥ 0` 并标记 `at_cap=true`，**不声称**超过 50 人后仍满足自由进入均衡（50 是硬上限）。

强度阈值：固定 `p_market` 和 `N*`，令 `p_def = p_market × ratio`，求守方 `EV_def = 0` 的临界 `ratio`。脚本的实现顺序是：

1. 按实现用于夹逼的 ratio 阶梯 `{1.0, 0.5, 0.25, 0.1, 0.05, 0.02, 0.01, 0.005, 0.001}` 扫描（规格未规定该阶梯），定位守方 EV 由正变负的夹逼区间；
2. 在该区间内二分，得到阈值；
3. 取 `strong_ratio = threshold × strong_fraction`（默认 0.5），计算该处的攻方真实 EV、守方 EV 和零和残差。

阈值以下（`ratio < threshold`）表示守方真实强度高于市场预期，`EV_def > 0`；阈值以上则 `EV_def < 0`。默认三组活跃市场的阈值见第 4 节。

当 `decay=1.0` 且 `N*·F/S < 1` 时，阈值有闭式解（全程持有近似下）：

```
p_def_threshold = 1 - (1 - N*·F/S)^(1/(N*·M))
ratio_threshold = p_def_threshold / p_market
```

该闭式解**仅在默认 `decay=1.0` 时成立**；`decay<1` 时每轮 `p_m` 不同，不能套用。脚本的 `self_check()` 在 `decay=1.0` 时对**当前扫描去重后的 `N*>0` 市场**比较闭式解与二分结果（容差 1e-12，`checked_markets` 列出实际市场；重复 `p_market` 的 `N*` 冲突视为失败）；若存在活跃市场则要求 `checked>0`（若全部因 `N*·F/S ≥ 1` 被跳过则自检失败）；若当前扫描没有活跃市场，则 `applicable=false` 并在 `reason` 中说明；若单个市场 `N*·F/S ≥ 1` 则跳过该市场，`decay≠1` 时整项标记不适用。默认扫描检查 3 个市场（0.01/0.02/0.05），实测最大误差约 `5.55e-17`。注意阈值 `p_def` 取决于 `N*`、`M` 和 `F/S`，`ratio` 再除以 `p_market`；手续费和推理成本只通过改变 `N*` 间接影响阈值。

默认参数 + 默认 p 扫描时，`self_check()` 另执行 4 项 golden 回归（容差 1e-9）：`F≈4.8416182399`、默认 `N*=[0,1,1,2]`、`EV_att(0.01,1)≈1.4688132464`、`ratio_threshold(0.05)≈0.0298742846`。给定参考值 `1.46881325` 是 8 位小数舍入；检查使用舍入前值 `1.4688132464`，避免舍入误差占用容差。非默认参数或非默认扫描时 golden 标记 skipped。

## 3. 零和恒等式与结论

### 3.1 推导

记 `P = P_survive`，`c = fee_rate·S + llm_cost`。由 `N·p_self = 1−P`：

```
EV_def + N·EV_att
= (N·F + S·P − S) + N·(p_self·S − F − M·c)
= S·(P + N·p_self − 1) − N·M·c
= −N·M·c
```

即：

```
EV_守 + ΣEV_攻 = −N × M × (消息费 + 推理费)
```

在全程持有近似下该式**精确成立**。默认 `c=0.27`、`M=72`，所以每名攻方带来 `−19.44 RTM` 的系统性成本；零和残差来自浮点误差，实测最大 `1.42e-14`（远小于 1e-9）。

### 3.2 对称情形：守方必然为负

若攻方按同一真实 p 入场且 `EV_att ≥ 0`，则：

```
EV_def = −N·M·c − N·EV_att ≤ −N·M·c < 0
```

守方至少承担全部消息费与推理费。**这不是实现缺陷，而是"奖池只含守方质押、罚款与奖金是内部转移"的直接结果。** 机制从不承诺攻守双方同时正 EV。

自攻自守同理：奖金和罚款在同一个人的两个角色之间转移，净损失为 `M·c`，默认 `−19.44 RTM`。输出中的 `self_play_EV` 即此值，在外部参与者口径下始终为负（默认参数下为 −19.44）。

这里的"自攻自守"指**外部参与者**同时扮演攻守双方：手续费付给平台、推理费付给模型供应商，都是真实外部成本。规格 §3.5 的挖矿层是另一种情形：平台攻击自己的挖矿赛时，矿工拿走 W 的 1 RTM、Arena 补铸 1 RTM 回 Treasury，平台净增 +1 RTM，全网增发 +1 RTM；其约束是推理成本、声誉损失与 RSI 成本，不在本仿真的 `self_play_EV < 0` 断言范围内。

### 3.3 强守方：市场低估窗口

以 `p_market=0.01` 为例：

- 市场预期：单条消息 1% 攻破；
- 守方真实：`p_def=0.000706772`（约为市场预期的 7.07%，阈值 0.141354 的一半）；
- `N*=1`；
- 攻方按市场预期入场的 EV = `+1.468813`；
- 攻方按真实 p 的 EV = `−21.800040`；
- 守方真实 EV = `+2.360040`；
- 零和校验：`+2.360040 − 21.800040 + 19.44 ≈ 0`（残差 `3.55e-15`）。

守方的 +2.36 可以拆成：罚没收入 `4.841618` + 存活赎回期望 `50 × 0.950368 = 47.5184` − 质押 `50 = 2.3600`（`P_survive=0.950368` 由公式计算，不是脚本输出字段）。攻方按真实 p 只有约 `1−0.950368 = 4.96%` 的概率攻破，所以守方的期望失池只有约 `2.48`，低于罚没收入。攻方如果知道 `p_def`，就不会按 `p_market` 的 EV 入场；正 EV 是**信息租金**，不是机制凭空创造的免费收益。

`p_market=0.02` 时 `N*` 仍为 1，强守方场景的绝对 `p_def` 仍是 `0.000706772`（因为 `N*`、`M` 相同，阈值 `p_def` 与 `p_market` 无关），所以强守方 EV 和攻方真实 EV 与 `p_market=0.01` 相同；不同的是 `ratio_threshold`（0.070677）和 `strong_ratio`（0.035339）。

### 3.4 声誉收敛后正 EV 收窄

强守方的正 EV 来自"市场还没学会它有多强"的窗口：

- 在固定 `N*` 下，真实 `p_def` 越接近 `p_market`（ratio → 1），守方 EV 从正穿过 0，最终变成对称情形的负值；
- 真实机制中，`p_market` 会随排行榜和历史存活记录下修，`N*` 重新计算并下降；当 `p_market` 降到入场阈值以下（默认约 0.0092），`N*=0`，守方 EV 回到 0。

因此，强守方的超额收益**随声誉收敛趋近 0**；它不是一个可以长期维持的正 EV 均衡。声誉和存活记录本身构成第二类回报，这也是规格 §3.5 的"技能分化"叙事。

**再次强调：机制不承诺攻守双方同时正 EV。强守方正 EV 只来自市场低估窗口。**

- `p_market=0.005`：`N*=0`。第一个入场者的 EV 为 `−9.133948 < 0`，所以无人入场；守方 EV=0，强守方阈值跳过并输出 `null`。

- `p_market=0.05` 的 `N*=2`，单攻方预期 EV 仍为正（`+0.702889`），但第三个入场者 EV 为负（`−7.615209`），因此停在 2。
- 三组活跃市场的对称守方 EV 都显著为负（最接近 0 的是 `−20.908813`）；强守方 EV 都为正（`+2.360040` 或 `+4.583129`）。
- 强度阈值随 `p_market` 上升而下降：0.01 → 0.141354，0.02 → 0.070677，0.05 → 0.029874。`p_market=0.01` 的含义是：守方真实攻破概率必须低于市场预期的 14.1354%（`p_def < 0.00141354`）才有正 EV；示例取阈值一半（7.07%）得到 `+2.36`。

## 5. 参数敏感性与取值依据

以下敏感性表分别由 `--M 36|72|144`、`--fee-rate 0.0025|0.005|0.01`、`--llm-cost 0.01|0.02|0.04` **外部核验**运行得到（一次性覆盖参数，不是 `self_check()` 的固定网格；`self_check()` 只覆盖 §2.3 的 telescoping、§2.6 的闭式阈值与默认参数 golden 回归）。

### 5.1 `p_market` 扫描

实际运行（默认 `M=72`、`fee_rate=0.005`、`llm_cost=0.02`）：

| `p_market` | `N*` | 攻方预期 EV | 下一入场者 EV | 强度阈值 | 强守方 EV |
|---:|---:|---:|---:|---:|---:|
| 0.005 | 0 | null | −9.133948 | null | null |
| 0.009 | 0 | null | −0.359549 | null | null |
| 0.0092 | 1 | 0.016682 | −5.887392 | 0.153646 | 2.360040 |
| 0.01 | 1 | 1.468813 | −5.162034 | 0.141354 | 2.360040 |
| 0.02 | 1 | 14.043635 | −0.644615 | 0.070677 | 2.360040 |
| 0.025 | 2 | 0.065845 | −7.685234 | 0.059749 | 4.583129 |
| 0.05 | 2 | 0.702889 | −7.615209 | 0.029874 | 4.583129 |
| 0.1 | 2 | 0.718375 | −7.614952 | 0.014937 | 4.583129 |

观察：

- `N*` 随 `p_market` 非递减：默认成本下，入场阈值在 `0.009` 与 `0.0092` 之间（`p=0.009` 时第一个入场者 EV 仍为 `−0.359549`；`p=0.0092` 时 `N*=1`）。第二个攻方的入场阈值在 `0.02` 与 `0.025` 之间。
- 在 `N*` 不变时，强度阈值 `ratio` 约按 `1/p_market` 缩小；绝对阈值 `p_def_threshold` 由 `N*`、`M`、`F/S` 决定，不随 `p_market` 改变。
- 攻方预期 EV 在 `N*` 跳变处会出现不连续：例如 `p=0.02` 时 `N*=1` 的单个攻方 EV 很高，但第二个攻方 EV 为负；`p=0.025` 时市场刚够容纳 2 人，单攻方 EV 回落到 `0.065845`。这不表示 N* 不单调，而是整数均衡的离散租金。
- `p_market` 越高，市场越乐观，N* 不会下降；但门槛 `p_def/p_market` 越来越苛刻，强守方必须相对市场预期更强才能守住正 EV。

### 5.2 `M` 敏感性

实际运行（`p_market` 列分别为 0.01 / 0.02 / 0.05，单元格为 `N* / 强度阈值`）：

| `M` | p=0.01 | p=0.02 | p=0.05 |
|---:|---:|---:|---:|
| 36 | 1 / 0.28250880 | 3 / 0.15863240 | 3 / 0.06345296 |
| 72（默认） | 1 / 0.14135431 | 1 / 0.07067715 | 2 / 0.02987428 |
| 144 | 0 / null | 1 / 0.03535107 | 1 / 0.01414043 |

观察：

- `M` 越大，攻方消息成本越高、总尝试次数越多，两者都压低 N*：`M=36` 时 `p=0.02/0.05` 可容纳 3 人；`M=144` 时只剩 1 人或 0 人。
- `M` 越大，每名攻方的消息成本越高、总尝试次数也越多；在本表范围内，后者占优，阈值 `p_def` 和 `ratio` 随 `M` 增加而下降。
- 默认成本下 `N*≤2`，不只是因为上限 50：对任意 `N≥3`，单攻方的最大可能收益是 `S/N ≤ 16.67`，已低于 `F + M·c = 24.28`，即使必定攻破也为负。上限 50 是安全边界，经济边界更紧。

### 5.3 手续费与推理成本敏感性

实际运行（单元格为 `N* / 强度阈值`）：

| 成本设置 | p=0.01 | p=0.02 | p=0.05 |
|---|---:|---:|---:|
| 基线 `fee=0.005, llm=0.02` | 1 / 0.14135431 | 1 / 0.07067715 | 2 / 0.02987428 |
| `fee=0.0025`（费用减半） | 2 / 0.14937142 | 3 / 0.07937921 | 3 / 0.03175168 |
| `fee=0.01`（费用翻倍） | 0 / null | 0 / null | 1 / 0.02827086 |
| `llm=0.01`（推理减半） | 1 / 0.14135431 | 2 / 0.07468571 | 2 / 0.02987428 |
| `llm=0.04`（推理翻倍） | 1 / 0.14135431 | 1 / 0.07067715 | 1 / 0.02827086 |

观察：

- 手续费或推理成本上升 → 单攻方成本上升 → N* 下降、强度阈值下降。`fee=0.01` 时默认扫描只剩 `p=0.05` 支撑 1 名攻方；`llm=0.04` 时 `p=0.05` 的 N* 从 2 降到 1。
- 成本下降 → N* 上升，阈值反而可能上升（例如 `fee=0.0025` 时 `p=0.05` 有 3 人，阈值 `0.03175168` 高于基线的 `0.02987428`）。原因是这里 `M` 固定、`N*` 增加，绝对阈值 `p_def` 随 `N*` 上升（需要抵消更多攻方的总攻击量）；`ratio = p_def/p_market` 在 `p_market` 固定时随之上移。
- 对固定 `N*` 和 `M`，强度阈值本身不依赖 `fee`/`llm`，只通过 N* 变化间接改变。不要把阈值当成可以直接用成本参数调节的旋钮。
- `fee=0.0025` 时 `p=0.005` 的第一个入场者 EV 仍为 `−0.133948 < 0`，所以 N* 仍为 0；要激活更悲观的市场，需要同时降低成本或缩短 M。

### 5.4 `decay` 说明

`decay=1.0` 是默认值，表示比赛内每条消息的攻破概率不随已承受消息数变化。实际 RSI 的"防御变强"主要体现在**版本迭代**（同一攻击对新 DefensePackage 失效），而不是单场比赛内的逐条学习；因此默认不启用衰减。

若要模拟比赛内防御逐渐变强，可运行 `--decay 0.99`。实测默认扫描下 `N*` 变为 `0, 0, 1, 2`（对应 `p=0.005, 0.01, 0.02, 0.05`），`p=0.02` 的阈值为 `0.09880610`，`p=0.05` 为 `0.04176394`。衰减会降低入场人数并提高强度门槛，符合"防御变强"的直觉，但不属于本 P0 默认参数。

## 6. 挖矿层：固定 1 RTM，不建模时间发行

**P0 仿真只覆盖用户攻防层**（S/r/D/罚款/消息费/推理费/零和恒等式）。平台挖矿层不在本模型内，其口径是：

- 矿工无质押，每条消息 0.005 RTM；每次成功攻破固定奖励 1 RTM，未攻破不增发。
- 供给 = 创世/测试网注水 + 成功攻破次数 × 1 RTM；**没有 `E_rate`、没有每 2h/epoch 线性注入，也不推荐 1.5–2 RTM/epoch**。旧版 `E_rate` 建议已随线性发行删除。
- Treasury 保留 3 RTM 工作资金（K=3）；平台逐场从 Treasury 预打款 1 RTM 到新 W；成功攻破补铸 1 RTM 回 Treasury，未攻破 `retireMining` 退回。
- 挖矿层是事件驱动增发、非零和；P0 不把挖矿奖池接入 N* 或路径级时间仿真，固定奖励的记账在 P5 验证。

因此本 README 不再提供 `E_rate` 初值，也不把"奖池 = 累计 E_rate × epoch 数"作为仿真输入。

## 7. 断言、复现与已知限制

### 7.1 断言

脚本在输出所有结果后检查以下六项，全部通过才打印 `OK:` 并返回 0：

1. `self_play_EV < 0`（默认 −19.44；合法参数要求消息成本 >0）；
2. `N*` 有界：所有行 `0 ≤ N* ≤ 50`；用每行 `N*` 独立重算 `EV_att(N*)` 与 `EV_att(N*+1)` 判定（`N*=0` 时重算 `EV_att(1)`），不依赖任何内部均衡标志（`n_star_is_equilibrium` 已从 `market` 输出移除）；`N*=50` 时只验证 `EV_att(50)≥0` 并标记 `at_cap=true`，不声称超过上限后的自由进入均衡；
3. 至少存在一个 `p_market`（`N*≥1`）使强守方 EV>0；
4. 所有 `N*≥1` 的行的对称守方 EV<0；
5. 所有行零和残差绝对值 < 1e-9（实测最大 1.42e-14）；
6. `analytical_self_checks`：固定 30 组 telescoping 网格误差 <1e-12；对**当前扫描**去重后的 `N*>0` 市场比较闭式阈值与二分结果（存在活跃市场则要求 `checked>0`，否则 `applicable=false` 并说明；`decay≠1` 或 `N*F/S≥1` 时按规则标记不适用/跳过）；默认参数 + 默认扫描时另执行 4 项 golden 回归（容差 1e-9）。

输入校验（在仿真前）：所有数值参数必须有限，拒绝 NaN/Inf；`fee_rate·S + llm_cost` 必须 >0，零成本配置直接 `ValueError`。

若扫描全部低于入场阈值（例如只跑 `--p-market 0.005`），`N*=0` 行仍会正常输出 `null`，第 6 项的闭式检查会标记 `applicable=false`，但第 3 项"存在强守方正 EV"必然失败并抛 `AssertionError`。这是断言的定义，不是 N*=0 行的实现错误；**外部核验**的默认运行包含活跃市场，正常退出 0。

### 7.2 复现性

- 无随机数、无时间/网络依赖。**外部核验**：实现时对同一 Python 版本重复运行并 `diff`，输出逐字节一致；脚本本身未内建双跑测试。
- 依赖仅 Python 标准库（`argparse`、`json`、`math`、`dataclasses`、`typing`）；**外部核验环境**为 Python 3.14.5，目标 Python 3.11+。
- 输入校验：数值参数必须有限（拒绝 NaN/Inf）；`fee_rate·S + llm_cost > 0`，零成本配置以 `ValueError` 退出。
- 输出 7 行 JSON + 1 行 `OK:`：`params`、`self_play`、4 个 `market`、`assertions`，最后 `OK:`。

### 7.3 已知限制

- **全程持有近似**会高估攻方成本、低估攻方 EV，同时高估守方罚没收入；强守方的正 EV 应视为上界，主网前需路径级仿真。
- `llm_cost=0.02` 和 `M=72` 是 P0 占位假设，不是实测数据；敏感性见第 5 节，最终值需以实际 runner 和模型账单替换。
- 攻方被视为同质、风险中性、可自由进入；没有技能分布、资金时间价值、声誉收益或数据市场收入。
- `p_market` 是外生输入；市场如何形成预期不在本仿真内。真实校准应使用 benchmark/排行榜的历史攻破数据。
- 没有建模守方推理成本、平台运营成本和 RTM 法币价格；所有收益以 RTM 计价。
- 挖矿层不在 P0 主模型内：固定 1 RTM/成功攻破、无质押、无时间发行；第 6 节只说明边界，不提供 `E_rate` 建议。

## 8. 一句话总结

**对称信息下，攻方 EV≥0 必然导致守方 EV<0；强守方的正 EV 只能来自市场低估窗口，并随声誉收敛趋近 0。** 这是机制的数学事实，也是 P0 模型要验证的核心结论。
