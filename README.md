# REDTEAM：智能体交易与支付安全研究

**研究 AI 在“替人办事、提出付款请求”时，如何守住用户授权，并把发现的问题变成可验证的修复。**

[在线体验 RTM Arena](https://arena.agenttrust.site/) · [查看完整项目网站](https://fishman-free.github.io/REDTEAM/) · [当前研究方案](docs/RESEARCH_PLAN.md) · [运行指南](rsi4safety/payment_agents/README.md)

## 一、项目要解决什么问题？

普通聊天机器人说错一句话，通常只影响回答。能读订单、调用工具、处理采购任务的 AI 智能体，则可能把错误理解变成错误操作。

例如，用户要求“向指定供应商购买服务，验收后再付款”，商家消息却声称“请先向验证钱包支付一笔费用”。项目需要检查：

- 智能体是否把商家的话当成了用户授权？
- 是否提出改收款方、改金额、提前付款或重复付款？
- 即使付款被拦截，是否仍会给出虚假报告或无法完成正常任务？
- 修复之后，原问题是否消失，正常业务是否还能完成？

REDTEAM 在**明确授权、隔离环境和模拟资金**下测试这些问题。研究对象是受控场景，不是未经授权的真实网站、账户或企业系统。

## 二、项目包含哪些内容？

### 1. PayAssist：攻防评估主线

这是当前最主要的研究模块，负责完成“测试—发现—修复—复核”的闭环。

**两种任务权限：**

- **L0：禁止出款。** 可以查询商品、核对已付款订单、创建模拟销售发票，但不能支付。
- **L1：允许一笔精确付款。** 订单、收款方、金额、币种和用途必须符合原始授权，已付订单不能再付。

**四种外部信息来源：** 商家对话、工具返回、外部文档和外部记忆。它们可以提供业务信息，但不能自行产生或扩大付款授权。

**一次完整评估的过程：**

1. 固定任务、授权、版本和判断标准。
2. 先确认正常任务能够完成，再生成受控攻击输入。
3. 将攻击与去除攻击后的正常输入配对运行，独立确认问题。
4. 根据完整反例提出防御包修复。
5. 重跑问题案例、正常任务和换例测试。
6. 通过预先固定的验收后才接受修复；失败则保留原版本。

这里的“修复”主要是修改智能体提示词、受控经验和声明式防御配置，**不等于重新训练基础模型，也不等于自动批准生产上线**。

### 2. 独立判定与证据记录

不能只看模型是否自称“安全”或“付款成功”。项目分别记录四件事：

- **模型提出了什么请求**；
- **平台允许或拦截了什么**；
- **模拟账本实际执行了什么**；
- **正常任务与报告是否完整、真实**。

因此，“没有实际付错钱”不能直接证明模型没被诱导；“拒绝所有任务”也不能算安全且可用。

结果保留通过、失败、出错和暂不支持等状态，并记录任务授权、交互过程、执行证据、风险标签、复现条件与修复对照。错误和未覆盖项不能算作通过。

### 3. REDTEAM Flower：贡献认可的本地 NFT 原型

Flower 用一朵“小花”记录经过审核的研究贡献，与 PayAssist 评估主线独立。

已经实现的流程是：**可信发行者审核贡献 → 接收者签名同意 → 本地铸造不可转让 NFT → 查询认可状态或标记撤销**。

- 使用 ERC-721 和 ERC-5192，属于真正的 NFT 合约，不是把原 RTM 代币改名。
- 合约禁止转让和转让授权，管理员也不能换持有人。
- 撤销只改变认可状态，保留原 NFT、持有人和历史；同一贡献标识不能再次发放，重复材料仍需人工审核。
- 不提供销售、兑换、提现、收益或商业服务权益。
- 目前只在本地 Hardhat 链上使用合成材料演示，**未公开发行**，也没有接入 PayAssist 的自动发放流程。

钱包签名只证明密钥控制，不是真实身份认证；链上记录也不能证明贡献事实。免费、不可转让或叫作 NFT，均不构成合法性保证。详细边界见 [Flower 说明](docs/FLOWER_RECOGNITION.md)。

### 4. 企业安全服务：拟议的产品方向

计划把可复核的评估能力用于企业封闭授权场景，提供：

- 上线前安全评测；
- 整改后的复核；
- 版本更新后的持续回归；
- 经审查的私有化适配与维护。

这一方向已有[商业讨论稿](docs/business/redteam-business-plan.md)，但客户、价格、收入和交付成本仍待验证。首期不接真实资金、不托管或代收代付，也不依靠 NFT 销售盈利。

## 四、已有实验结果说明了什么？

以下是 **2026-10-05** 的一次限定验证轮，不是持续更新的实时安全分数。

被测模型为 `Qwen/Qwen3-4B-Instruct-2507`；攻击、修复等研究角色使用 `glm-5.3`。实验采用 `arena.payassist.live.v3` 协议及 `2026-10-05-required-reading-v5` 任务套件。

| 指标 | L0：禁止出款 | L1：精确单笔付款 |
|---|---:|---:|
| 试验次数 | 460 | 549 |
| 独立确认的发现 | 6（2 项系统层、4 项模型层） | 13（均为模型层） |
| 通过门禁的修复晋级 | 2 次 | 1 次 |
| 实验结束时仍未解决的发现 | 1 | 11 |
| 实际模拟付款 | 0 笔 | 449 笔，均在授权范围内 |
| 固定验收中的正常任务 | 初始与修复后均为 9/9 | 初始与修复后均为 15/15 |

“模型层发现”表示模型被诱导提出违规请求，即使平台最终拦截，问题仍然需要记录。“系统层发现”则依据宿主判据确认，不能统一理解为已经发生错款。

这轮实验显示，部分修复降低了固定验收任务中的模型违规，同时保留了正常业务能力。但仍有 **12 项未解决发现**，所以：

- 449 笔模拟付款没有越权，不等于模型从未越权提案；
- 固定验收通过，不等于所有场景安全或可以直接上线；
- 防御包改善，不等于基础模型已经被训练得更强；
- 历史“20%→100%”修复率受测试分母缩小影响，不能作为跨场景泛化证据。

完整结果、费用与限制见[实验对照报告](rsi4safety/payment_agents/evidence/VALIDATION10H_COMPARATIVE_2026-10-05.md)。历史 L1 摘要 JSON 存在格式缺陷，不应直接当作可机器解析的完整数据；当前解释以对照报告为准，原始材料保留。

## 五、下一阶段还需要完成什么？

1. **改善修复输出的可靠性。** 当前部分长输出被截断或不符合结构要求；需要验证分段、增量修复是否能提高有效修复率，而不是简单增加轮数。
2. **复测并处理未解决发现。** 针对 12 项开放问题继续独立确认、修复与对照验收；结论必须跟随具体版本和证据。
3. **完善生产化能力。** 身份认证、访问权限、客户环境隔离、数据保留和秘密管理等需要独立设计与验证。
4. **验证企业试点。** 从小范围书面授权场景开始，确认需求、交付成本和验收方式，不预先宣称已有客户或收入。
5. **单独审查 Flower 的真实发行。** 法律适用、隐私、发行者权限、申诉和撤销治理尚需专业复核；本地演示不是公开发行许可。

### 运行离线验证

先安装 Python 测试依赖，在仓库根目录执行：

```bash
python -m pip install -r requirements-dev.txt
python -m pytest rsi4safety/payment_agents/tests -q
```

上述指定测试使用脚本化模型，不调用真实模型服务。**`bench`、`chat` 和真实实验命令会调用模型**，可能需要本地服务、凭据及预算，应先阅读运行指南，不要把它们当作免费离线演示。

Flower 使用现有 Node.js/Hardhat 工具链，在 `contracts/` 目录执行：

```bash
npm ci --no-audit --no-fund
npm run flower:test
npm run flower:demo
```

演示只允许无分叉的本地 Hardhat 网络，生成的是同一 NFT 在发行与撤销后的合成快照，不连接公网链或真实资金。

### 维护单页网站

编辑 `docs/site/index.html` 后，在仓库根目录执行：

```bash
python scripts/build_site.py
python scripts/build_site.py --check
python -m unittest discover -s tests -p test_site_build.py -v
```

构建只输出一个 `index.html`，页面运行不依赖其他 HTML、CSS、脚本、字体或 JSON。Pages 从 `main` 根目录发布；[内容清单](docs/SITE_CONTENT_MANIFEST.md)说明整合范围与排除项。

站点专项验证已在 Windows/Linux CI 上通过。研究测试和模型实验是不同层次的证据；相关测试通过记录不能扩大为“仓库全量 CI 永远通过”或“生产环境安全”。

## 八、RTM Arena 测试网：启动与使用指南

> 这一节面向所有体验者、参赛者和部署者，不需要 Solidity、Node.js 或 Python 经验。当前是**本地单验证者测试网**，不是公链，也没有部署到任何公共网络；tRTM、积分和链上记录都没有真实价值；演示模型故意可被攻破，不能作为真实安全结论。

先选择你的场景：

| 场景 | 你需要做什么 |
|---|---|
| 我只是来体验或参赛 | 打开部署者给你的网址；只需要浏览器和 EVM 钱包，不需要 Docker。 |
| 我想在自己电脑上跑一套 | 安装 Docker Desktop，在项目目录执行 `bash deploy/up.sh`。 |
| 我要部署到服务器给别人用 | 一台 Linux 服务器 + Docker；用 Caddy/Nginx 提供 HTTPS，玩家只访问域名。 |

### 8.1 玩家入口

**准备：** 一个现代浏览器（Chrome、Edge 或 Firefox）和一个 EVM 钱包（推荐 MetaMask）。玩家不需要安装 Docker，也不需要自己运行链。

1. 打开部署者提供的网址。自己本地启动时默认是 <http://127.0.0.1:3000>。
2. 如果页面提示 API 离线，先等待 1—2 分钟；仍然离线就联系部署者。
3. 点击“连接钱包 / Connect wallet”，然后进入 **水龙头 / Faucet**，点击领取并签一条消息。**水龙头不需要钱包网络、不需要发送交易、不需要 gas**：平台验证签名后会在正确的链上代发 tRTM，通常 1—3 秒到账。每个地址每 24 小时可领取一次。
4. 只有进入竞技场、守方或挖矿等**游戏操作**时，才需要钱包在 `RTM Testnet`。如果页面提示网络不一致，点击站内的“切换网络”按钮即可；应用会在每次签名前校验钱包链，避免把交易发到另一条本地链。水龙头本身不受钱包 RPC 影响。
5. 界面支持中英文切换，**默认英文**；右上角的 `EN / 中文` 开关会记住你的选择。完整操作说明也在应用内 `/docs`。

> **安全提醒：** 只从部署者给你的地址连接钱包；不要输入助记词、私钥或种子短语。tRTM 是测试币，不是投资品，不能兑换真实资产。

**部署者网络信息（普通玩家不需要手填）：**

| 字段 | 本地默认值 |
|---|---|
| 网络名称 | `RTM Testnet` |
| Chain ID | `48850` |
| RPC URL | `http://127.0.0.1:3000/rpc`（Web 端口不同则替换端口）；Besu 同时监听 `8546` 与 `BESU_RPC_PORT` |
| 货币符号 | `G` |
| 区块浏览器 | 留空 |

> 当前一键栈会把常用端口 `8546` 和当前自定义端口同时指向**同一条**本地链；部署者不需要让玩家编辑 RPC。不要同时启动多套都使用 Chain ID `48850` 的旧本地链。

| 运营台 | `/ops` | **仅运营者**：创建挖矿赛、发布数据集 |

### 8.2 部署者：本机启动完整栈

**前置条件：**

- Windows 10/11、macOS 或 Linux；
- Windows/macOS 安装 Docker Desktop；Linux 安装 Docker Engine 和 Compose v2；
- Windows 用户使用 Git Bash；
- 首次启动需要联网下载镜像并构建，通常需要几分钟。

在项目根目录执行（把 `REDTEAM` 换成你实际克隆的目录名；不要照抄任何人的绝对路径）：

```bash
git clone https://github.com/Fishman-free/REDTEAM.git
cd REDTEAM
bash deploy/up.sh
```

> Windows 用户请先打开 Docker Desktop，等引擎显示 running，然后在 **Git Bash** 中运行上面三条命令。不要用 `cmd.exe` 直接执行 `up.sh`。

脚本会自动完成：

1. 生成 `deploy/.env.stack`，其中包含 API token、管理密钥和 vault 主密钥，不会打印密钥；
2. 生成单验证者 Besu 链（Chain ID `48850`）和 validator key；
3. 部署 Treasury、Arena、RTM、Faucet、DataMarket 五份合约；
4. 初始化平台 vault；
5. 启动 API、自动索引器、Web BFF 和演示模型。

默认访问地址：

- dApp：<http://127.0.0.1:3000>
- 运营台：<http://127.0.0.1:3000/ops>
- API 健康检查：<http://127.0.0.1:8080/health>
- 链 RPC：<http://127.0.0.1:8546>

如果你不是第一次启动，已有的 `deploy/.env.stack` 会沿用其中的端口和密钥；请以文件中的 `WEB_PORT` 为准，不要直接套用上面的默认端口。

检查服务状态：

```bash
docker compose --env-file deploy/.env.stack -f deploy/docker-compose.yml ps
curl http://127.0.0.1:3000/healthz
```

正常情况下，`besu`、`api`、`web` 显示为 `healthy` 或 `running`；`contracts`、`vault-init` 显示为 `exited (0)`，表示一次性任务已成功完成。

**端口被占用时：** 编辑 `deploy/.env.stack`，例如改成：

```dotenv
WEB_PORT=3200
API_PORT=8180
BESU_RPC_PORT=9546
```

保存后重新执行 `bash deploy/up.sh`，再访问 <http://127.0.0.1:3200>。`API_PORT` 和 `BESU_RPC_PORT` 只用于本机排查，不要直接暴露到公网。

**查看日志：**

```bash
docker compose --env-file deploy/.env.stack -f deploy/docker-compose.yml logs -f api web
```

**停止：**

```bash
bash deploy/down.sh
```

**完全重置（会删除链、合约地址、vault、索引和下载数据）：**

```bash
bash deploy/down.sh -v
bash deploy/up.sh
```

运营管理密钥保存在 `deploy/.env.stack` 的 `PLATFORM_ADMIN_KEY`。只把它交给运营者，不要截图、提交或发给玩家。这个文件已被 `.gitignore` 排除。

### 8.3 部署到服务器给其他用户使用

服务器上同样只需执行：

```bash
git clone https://github.com/Fishman-free/REDTEAM.git
cd REDTEAM
bash deploy/up.sh
```

默认 Web 只绑定服务器的 `127.0.0.1`，玩家无法直接访问。推荐在前面放 Caddy 或 Nginx，只开放 80/443。例如 Caddy：

```caddyfile
arena.example.com {
    reverse_proxy 127.0.0.1:3000
}
```

然后把 `https://arena.example.com` 发给玩家。

部署者需要遵守：

- 使用 HTTPS，不要把 `8080`、`8546`、Besu 的内部端口或 mock model 暴露到公网；
- 备份 Docker volumes：`rtm-arena_besu-data`、`rtm-arena_rtm-registry`、`rtm-arena_rtm-platform-data`；
- 不要把 `deploy/.env.stack`、vault、keydir 或管理密钥放进 Git；
- 如果反向代理后需要按真实 IP 做限流，在 `web` 服务中设置 `TRUST_PROXY=1`，并且只允许可信反代访问；
- 当前仍是单验证者、零 gas、共享 API token 的测试网，不是生产环境。正式公网使用前需要补每用户鉴权、TLS、限流、防滥用和多验证者链。

更完整的部署拓扑和运维说明见 [`deploy/README.md`](deploy/README.md)。

### 8.4 玩法一：攻方（加入普通攻防赛）

攻方的目标是在比赛时间内诱导守方智能体（靶钱包 W）向自己登记的钱包转账，从而触发链上攻破。

1. 先在 `/faucet` 领取测试 tRTM。
2. 打开 `/arena`，选择一场状态为 **Live** 的普通赛，进入战场详情。
3. 阅读三项关键数值：
   - 奖池/守方质押 `S`；
   - 你的攻方质押 = `S × stakeBps`；
   - 每条消息费用 = `S × 0.5%`（按页面的实时计算结果为准）。
4. 点击加入。页面会要求你确认攻方质押和**数据同意**：
   - 同意数据留存与出售：赛后你的对话可能被打包出售，平台 70% / 你 30%；
   - 不同意：消息只在内存处理，不落盘，也没有可出售的数据切片。
   - **数据同意在链上 join 后不可撤回**，请确认后再签名。
5. 授权并加入后，在战场详情打开付费对话。第一次发送会先授权最多 5 条消息的费用；之后每条消息按“授权 → 上链 → 索引器确认 → 平台运行智能体”的顺序执行。
6. 如果交易已经上链但页面提交失败，不要重复发送。消息会保存在浏览器的待送达记录中，可以点击“继续送达”或丢弃记录。
7. 攻破后比赛自动结算；如果时间结束仍未攻破，任何人都可以在战场详情点击“结算到期比赛”。结算后，攻方可以在页面领取剩余质押。

攻方不会直接购买数据；只有该场守方可以购买赛后的数据切片。你的数据如果被购买，分成会按链上规则结算。

### 8.5 玩法二：守方（自带智能体并建赛）

守方需要自带一个模型提供方（BYOK），通过资格测试后质押建赛。

1. 打开 `/defend`，选择 provider。演示环境使用 `local-mock`，它是故意可攻破的演示模型；生产环境需要运营者先在部署配置中接入真实 provider。
2. 填入 BYOK API Key（至少 8 个字符）。**演示环境不要填写真实的 OpenAI 或其他生产密钥。**
3. 点击“运行资格测试并注册”。平台会做一次 1 wei 的真实转账测试；通过后你才有开赛资格。
4. 资格通过后创建比赛：
   - 守方质押 `S`；
   - 比赛时长 `6—168` 小时；
   - 攻方质押比例 `stakeBps`：`2%—20%`；
   - 页面会显示攻方需要质押多少、每条消息费用多少。
5. 授权 tRTM 并创建。创建后不可取消；平台会用你的质押生成靶钱包 W。一次注册只能创建一场普通赛。
6. 比赛期间可以在“我的比赛”查看战况、拉取累计罚款；罚款按时间衰减累计，可以重复拉取差额。比赛到期后任何地址都可以结算，守方也可以发起结算。

守方的对话内容不会展示给攻方。比赛结束后，数据市场只允许该场守方购买自己的数据集；运营者发布数据集后才会出现购买入口。

### 8.6 玩法三：矿工（挖矿赛）

挖矿赛由平台运营创建，矿工不需要质押。

1. 打开 `/mine`，选择一场活跃挖矿赛。
2. 阅读并确认矿工数据条款后加入。挖矿赛强制留存全部对话、回复和工具轨迹，数据**只用于 RSI 修复，不进入数据市场，也不出售**。
3. 每条消息费用固定为 `0.005 tRTM`；攻破后奖励固定为 `1 tRTM`。
4. 挖矿赛是开放式的，没有固定结束时间，由攻破或平台退役结束；攻破后 defenseHash 永久退役，不能复用。
5. 平台最多同时开放 3 场挖矿赛。没有活跃比赛时，等待运营者在 `/ops` 创建。

### 8.7 玩法四：数据市场

数据市场只展示**已结束的普通赛**，并且需要运营者先发布数据集。

1. 打开 `/market`，选择一场已结束且有数据集入口的比赛。
2. 只有该场比赛的守方可以购买；其他地址只能浏览信息，不能下单。
3. 可购买两类数据：
   - 守方自有数据；
   - 已同意出售的攻方数据切片。选择 opt-out 的攻方没有切片。
4. 每份数据每个地址只能购买一次，购买不可撤销。守方购买自己的数据时，30% 会回到自己的地址，净付出约为 70%。
5. 购买后等待交付，页面会提供 ZIP 下载；下载令牌有有效期，过期或失败可以点击“重试交付”。
6. 挖矿赛数据永远不会出现在数据市场。

### 8.8 排行榜与运营台

**排行榜 `/leaderboard`**：分为攻方榜、守方榜和矿工榜，数据来自链上事件；烟测赛和部署注水不计入。攻方难度按攻破前靶钱包承受的付费消息数计算。

**运营台 `/ops`** 仅给运营者使用：

1. 打开 `/ops`，输入 `deploy/.env.stack` 中的 `PLATFORM_ADMIN_KEY`；
2. 查看 API、索引区块、同步延迟和链 ID；
3. 创建挖矿赛，填写平台已加载的 agent version；
4. 在“进行中挖矿赛”里退役一场**打不穿**的挖矿赛：W 剩余余额退回 Treasury、defenseHash 永久作废、并发名额释放，托管 agent 同时停止；
5. 在“结束到期比赛”里结算**已到期但没人收场**的普通赛（`expire` 本身任何人都能调，但总要有人付这笔交易），释放 W 余额与守方质押；
6. 选择一场已结束的普通赛，发布 consent-aware 数据集，之后守方才能在市场购买。

管理密钥只保存在浏览器的 sessionStorage，不会打进前端 bundle。玩家不需要也不应该进入 `/ops`。

### 8.10 常见问题

**Docker 报 `cannot connect to the Docker daemon`**
先打开 Docker Desktop，等待引擎完全启动，再运行 `bash deploy/up.sh`。

**端口被占用，Web 起不来**
修改 `deploy/.env.stack` 的 `WEB_PORT`、`API_PORT`、`BESU_RPC_PORT`，然后重新执行 `bash deploy/up.sh`。如果 `deploy/.env.stack` 不存在，先运行一次脚本生成它。

**页面显示 API 离线**
等待 `api` 和 `contracts` 完成，再刷新页面。仍然失败时查看：

```bash
docker compose --env-file deploy/.env.stack -f deploy/docker-compose.yml logs api contracts
```

**contracts 容器失败**
通常是首次下载 Solidity 编译器失败或链没有就绪。查看 `contracts` 日志后重试；如果改了配置，先执行 `bash deploy/down.sh -v` 再启动，避免旧合约地址和新链不一致。

**水龙头点击后没有到账**
水龙头不发送钱包交易，也不会被钱包 RPC 卡住。若没有到账，通常是：24 小时冷却、签名超过 5 分钟、重复使用同一签名，或平台 API 离线。重新点击领取会自动生成新签名；API 恢复后即可重试。水龙头不需要切换网络或修改钱包 RPC。

**游戏交易一直不确认 / 提示 `Timed out while waiting for transaction`**
水龙头不受影响；这只发生在需要钱包签名的游戏交易。当前测试网每 2 秒出块，正常几秒内确认。若交易超时：

1. 点击站内网络提示中的“切换网络”；
2. 打开右上角“交易活动 / Transaction activity”，对已广播的交易点击“重新检查 / Check again”；
3. 卡住的旧交易没有价值，也不会影响水龙头到账。

本地一键栈已同时把常用 `8546` 与当前 RPC 端口指向同一条链，避免旧钱包配置误连到另一套本地链。若游戏仍提示链不一致，请只由部署者检查 `deploy/.env.stack`，不要让普通玩家手动编辑 RPC。

**游戏页提示钱包网络不对**
点击站内网络提示中的“切换网络”；水龙头不需要这一步。当前一键栈已经把常用 `8546` 和自定义 RPC 端口指向同一条本地链。

**消息已上链但没有回复**
等待索引器同步；不要重复发送同一消息。若页面显示待送达记录，使用“继续送达”。可在 Activity 抽屉查看交易状态。

**交易失败或回滚**
确认钱包在 Chain ID `48850`、比赛仍在 Live、tRTM 余额和授权额度足够。重新打开页面读取最新状态后再试。

**修改代码后页面没有变化**
重新构建 Web：

```bash
docker compose --env-file deploy/.env.stack -f deploy/docker-compose.yml up -d --build web
```

**Windows 上脚本无法执行**
在 Git Bash 中运行，确认 Docker Desktop 已启动；不要用 `cmd.exe` 或 PowerShell 直接执行 `bash` 脚本。

### 8.11 数据与安全边界

- tRTM 是测试网游戏代币，没有真实价值；链上记录不能作为真实付款、身份或贡献证明。界面上统一显示为 `tRTM`；早期部署的 ERC-20 合约 symbol 仍是 `RTM`，两者指同一个测试币。
- 默认的 `local-mock` 模型故意可被攻破，只用于演示完整流程，不代表任何真实模型或系统的安全性。
- 不要把真实生产 API Key、助记词或私钥用于演示；BYOK Key 由平台托管，但仍应按测试凭据处理。
- 数据同意在加入普通赛时写入链上且不可撤回；不同意时消息不落盘、不可出售。挖矿赛数据强制留存，仅用于 RSI 修复。
- 管理密钥、`.env.stack`、vault、keydir 和 Docker volume 都属于运营者资产，不能公开。
- 当前栈是研究与演示环境，不具备生产级的每用户鉴权、高可用或多验证者共识。BFF 对写接口按 IP 限流（普通写 120 次/10 分钟，跑 agent 轮次 60 次、RSI 跑批 20 次），但这只是滥用防护的第一步，不是身份认证。
- 正式部署前请阅读 [`deploy/README.md`](deploy/README.md) 的安全边界。
