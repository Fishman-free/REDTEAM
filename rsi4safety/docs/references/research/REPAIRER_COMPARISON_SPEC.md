# P2 实验规格：修复者三条件对照（"修复者究竟有没有变强"）

依据评审判断制定。本实验回答唯一问题：**拿到同样的漏洞证据后，进化后的修复者是否比原始修复者更好？**

## 1. 实验材料：按根因分离的未见过修复任务集

- 现有 12 个预置漏洞按根因归并为 8 个独立根因家族（评审要求显式化）：
  1. 外部回执/取消声明被当事实（S1/S9/S11：receipt-trust）
  2. 外部内容并入决策上下文（S3：context-inclusion）
  3. 数值/币种字符串解析（S4/S7：parsing）
  4. 幂等/防重放绑定错对象（S5：idempotency）
  5. 预算快照时点（S6：budget-snapshot）
  6. 外部确认洗白（S2：confirmation）
  7. webhook 结构化事件直转付款（S10：event-command）
  8. 外部币种备注覆盖（S12：currency-override）
- **任务集构造**：对每个根因家族写一个"任务卡"：`{seeded-v0 源码 + 一份可信反例证据（从历史战役证据束导出或离线重放生成）+ 通过判据（该根因的反例不再复现 + 开发套件全绿）}`。
- **未见性保证**：策略改进阶段（第 2 步）只允许使用 evolve3 已修家族（receipt-trust 家族——evolve3 修的正是它）的轨迹；任务集里 receipt-trust 家族只作为"已见对照组"，其余 7 个家族为**未见实验组**。攻击机制与 evolve3 开发套件不重叠（任务卡验收只做回归，不参与策略形成）。

## 2. 三个条件（同一基础模型 glm-5.3-flash、同一权限、同预算）

| 条件 | 智能体工作区 | 预算 | 排除的替代解释 |
|---|---|---|---|
| A 固定修复者 | evolve3 之前的干净种子工作区（无记忆） | 每任务 96 轮 | 普通自动修复就足够 |
| B 仅经验记忆 | evolve3 防御者工作区**去掉技能/宪章更新**（只留 MEMORY.md+情景日志） | 同上 | 收益只来自多看经验 |
| C 受控自改修复者 | evolve3 防御者完整工作区（宪章+技能+记忆，即"进化后修复者"） | 同上 | — |

- 实现方式：三个 Docker 卷快照。A/B 从 evolve3 前的干净 seed 重建；C 直接用现有 `arena-evolve3-defender-ws` 卷（已保留）。
- 每个条件×每个任务卡独立会话执行修复，`apply_promotion` 流程照常（门禁=平台可信执行，不依赖内部攻击者重跑）。

## 3. 度量（每条件汇总 + 逐任务）

1. **未见根因修复成功率**（7 个未见家族中通过门禁的比例）——主指标
2. 修复后合法功能保持率（开发套件 benign 完成率）
3. 新引入问题数（回归集中新增失败）
4. 每个有效修复的成本（输入/输出 token、轮次、时钟时间）
- 显式记录负结果口径：C 不优于 A→自修改无额外价值；C≈B→收益来自经验记忆而非策略；C≈A→任务过易（用 A 的绝对成功率判断，A>85% 视为天花板效应）。

## 4. 后续扩展（本实验跑通后）

- 策略晋级路径（第二类候选产物）：`汇总已修复轨迹 → 提出修复流程改进（如"先建任务-授权对象-动作对应关系再定位缺失检查"）→ 在其他修复任务上 A/B 新旧策略 → 策略晋级`，与目标补丁共用版本库语义（V = 目标版本 × 策略版本 × 评测协议版本），策略回滚需撤回对应活动记忆规则。
- 外部提交协议：攻击包 = `{精确版本、前提、动作、声称违反的性质}` 的可重放材料；事实判定（可信执行）与解释判定（法官）分离；按独立根因计分而非提交数；发现成立与修复成功为两个独立生命周期。

## 5. 验收集定位声明（评审指出）

当前冻结终局套件参与接受/回滚决策，**性质是验收集而非独立泛化测试集**。任何对外表述以此口径为准；独立泛化检验留给任务集的未见家族与本实验。

## 6. 预算估计

8 任务卡 × 3 条件 × ~15 万输入 token ≈ 360 万输入/120 万输出（flash），约 4-6 小时机器时；无攻击者/法官长会话（反例材料已固化）。
