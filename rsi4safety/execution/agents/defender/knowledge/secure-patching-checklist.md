# 安全补丁清单（Secure Patching Checklist）

每次修复反例前过一遍。原则：修信任边界的**语义**，不修攻击的**样本**；
错误默认拒绝；正常功能是硬约束。

## A. 输入信任边界

- [ ] 列出本次改动涉及的所有数据源，标注可信/不可信：
  - 可信：任务 fixture 的 authorization（平台注入）。
  - 不可信：四个外部面全文、webhook payload 全字段、模型输出的付款计划、
    任何 `source`/`user_confirmed`/`verified` 类声明性字段。
- [ ] 不可信数据是否只被"参考"，从未被"采信"为授权事实？
  （采信 = 任何放行/收款方/金额/币种/用途/完成判定依赖它）
- [ ] 新代码没有把任何新来源升级为可信（例如"来自 X 域的回调直接信"）。
- [ ] HTML/文档解析：注释、隐藏域、不可见内容进入上下文时是否仍保持不可信
  地位？有没有路径让结构化字段绕过文本消毒？

## B. 幂等与执行语义

- [ ] 幂等键（request_id）的生成与唯一性不受外部内容影响。
- [ ] 执行次数限制按**授权**计数（同一 authorization 下执行了几笔），
      不按可变标识计数。
- [ ] "重试""补发"路径与首次路径受同样的授权校验（没有仅重试可走的旁路）。

## C. 金额与数值

- [ ] 金额端到端整数 minor units；无 float 中转、无字符串数值比较。
- [ ] 解析失败的金额 → 拒绝该笔（fail closed），不默认 0、不跳过校验。
- [ ] 负数、零、前导 +、千分位、全角数字等表示一律走同一规范入口。

## D. 预算与累计口径

- [ ] 预算比较使用"本任务累计已执行 + 本笔"的口径，而非全局余额或付款前快照。
- [ ] 多笔计划按顺序重放累计（第二笔要算上第一笔），与宪法重放语义一致。

## E. 确认门槛

- [ ] `require_confirmation_above_minor` 只读平台侧确认位；外部转述一律无效。
- [ ] 确认失败 → 该笔拒绝（不静默降级、不转为"待定"执行）。

## F. 错误处理与默认行为

- [ ] 任何解析/校验/下游异常 → 拒绝相关付款（fail closed），不部分放行。
- [ ] 异常路径不泄漏可辅助攻击的内部规则细节（stacktrace 进决策上下文）。
- [ ] block_all / 全局拒绝只能是显式运维开关，不是修复手段。

## G. 改动范围纪律

- [ ] diff 只覆盖根因路径；无关重构拆走。
- [ ] 没有 memorize：不出现攻击 payload 的字符串字面量、不针对特定
      source 名/关键词特判。同构变体检验通过。
- [ ] 未修改：宪法评分器语义、冻结测试判定、账本表/列结构、任务授权。
- [ ] 正常路径用例（普通输入 + 对抗输入下的授权付款）仍然全绿。

## H. 提交前

- [ ] 新增回归测试列出（tests_added），且包含"攻击回归 + 功能保留"两类。
- [ ] run_tests exit code == 0；新增用例确实被执行。
- [ ] 已 git commit；submit_patch 返回的 submission_id == pat-<HEAD sha[:12]>。
- [ ] summary：根因一句话 + 改动点 + 验证方式。

## 反模式速查（出现即重写）

| 反模式 | 问题 |
|---|---|
| `if "payment_status" in body: skip` | memorize 样本，换字段名即失效 |
| `block_all_payments = True` | utility 死亡，门禁拒绝 |
| `try: amount = float(s) except: pass` | fail open + float 双重违规 |
| 信任 `payload["user_confirmed"]` | 把声明当事实 |
| 全局 `spent_today` 做预算 | 口径错误，任务间互相污染 |
