# REDTEAM 国内合规化阶段报告

**报告日期：2026-10-10｜源码与事实基线：`main@b160351`｜性质：阶段梳理，非法律意见或合规认证。**

本文独立说明面向中国大陆落地的产品边界、现有控制与上线阻断项，不替代区块链实现、前端或宣传专项报告。依据仓库现有源码、当前 Markdown、官网编辑源及历史材料整理；本次未访问法律网站、未核验现行法规、未重跑测试或模型实验、未发布网站或合约。下文“已实现”限于可见研究实现，“已有验证”指引用既有记录，不表示本次新增验收。

## 一、TL;DR：完成的是路线收敛，不是“已经合规”

1. **商业定位已经明确成文**：拟提供企业封闭、书面授权的智能体安全评测、整改复核、持续回归及经审查的私有化维护；拟按人民币服务合同结算、开票纳税，不以代币销售、交易、融资、支付托管或 NFT 权益形成收入。尚无经核实的签约客户、收入或完成开票纳税的证据。
2. **研究实现已有部分实质约束**：PayAssist 的宿主授权、模拟账本与控制/攻击凭证分离，以及 Flower 的不可转让、禁授权、接收签名、贡献标识防重发和撤销机制，均有源码与既有验证记录。它们不是公司治理、商业授权或监管准入的替代品。
3. **历史 RTM 仍然存在且可转让**：它是真正的 ERC-20 研究合约，不是无交易积分，也未改名成 Flower。当前商业方案排除 RTM，当前 PayAssist 不接该奖励路径；公开仓库仍保留其源码和历史说明，不能称“已删除全部代币代码”。
4. **Flower 是独立、本地 NFT 原型**：仅有无分叉 Hardhat 31337 的合成演示，未公开发行、未部署主网。免费、不可转让、无经济权益是实质设计限制，但不是规避监管的标签或当然安全港。
5. **公开上线的是单 HTML 静态展示**：依据当前 README 与发布清单，GitHub Pages 展示站已上线；它不运行后端、付款、领取、发行或交易。网站公开不等于 NFT 已发行，更不代表经营、法律、隐私或生产安全已获批准。
6. **下一阶段仍被治理门禁阻断**：经营主体与责任、正式合同及测试授权、数据处理与供应商安排、私密漏洞流程、备案/许可适用判断、Flower 发行治理及正式专业审查均未完成到可核验的商业运行状态。

**阶段判断：已完成国内落地方向与风险边界的文档化，具备部分本地技术控制；尚未完成国内经营与公开发行的正式审查、手续和运营闭环。**

## 二、当前阶段：什么已做，什么还没有做

### 2.1 服务主线已收敛，但商业闭环仍是方案

[当前商业讨论稿](../business/redteam-business-plan.md)与[官网服务正文](../site/index.html#services)已把购买对象定义为有限范围的评测和复核交付，而不是付款能力、金融资产或“绝对安全证书”。候选收入包括项目评测、整改复核、年度回归和私有化维护；客户、价格、购买意愿及成本均待验证。

拟议交付包包括目标与授权范围、冻结版本和环境、正常/攻击配对证据、整改差异、回归结果、覆盖分母、开放发现、人工签收及保留安排。**人民币合同、开票和纳税目前是拟议经营要求，不是已经签约、已经开票或已经纳税的完成记录。** 工具名 `create_invoice` 只代表模拟销售账单/收款请求，不是税务发票系统。

当前路线不包括虚拟货币发行融资、兑换与交易市场、投资收益、交易撮合、付费导流、代收代付、资金托管或清结算。服务收入不依赖 Flower 的出售、持有、成交量或使用权。普通数据库、访问控制与签名记录即可支撑首期方案，区块链不是商业必需条件。这些是产品选择和停线边界，不是对所有同类业务的法律定性。

## 三、RTM、Flower 与公开网站的准确边界

### 3.1 RTM：排除商业路线，不改写历史事实

[RTMToken 源码](../../contracts/src/RTMToken.sol)继承 ERC-20，未加入 Flower 式转让禁用；其发行预算限制不消灭已发行 token 的转让能力。[BountyVault](../../contracts/src/BountyVault.sol)与[旧设计](../references/research/RTM_BOUNTY_DESIGN.md)研究的是预算、认领和结算，不自动判断攻击价值，也不保证未来兑付。旧 Arena 的本地证据桥不能被描述为当前 PayAssist 已实现公共领奖。

当前商业稿和官网明确排除 RTM、兑换及迁移，Flower 与其是不同合约及不同产品约束。**这一收敛是真实的路线区隔，但不能扩大成旧源码不可执行、已销毁既有资产或完成所有生产隔离审计。** 商业版上线前仍须检查实际部署清单、接口、营销、条款和资金流，避免研究入口被意外接入。

### 3.2 Flower：技术锁定是真实限制，治理缺口也是真实的

[ContributionFlower](../../contracts/src/ContributionFlower.sol)已实现发行者权限、EOA 接收者 EIP-712 签名、nonce/期限/domain/政策版本约束、贡献标识唯一性；转让和转让授权被拒，底层更新禁止转让与销毁。没有管理员换持有人、代理接收、钱包迁移或焚毁后换人重发入口。撤销只改变认可标志，原 token、owner 和贡献关联保留。

当前产品无销售、定价、兑换、赎回、分红、收益、算力、治理、服务优先级或公司所有权特权；持有 Flower 不作为商业服务资格。免费只指合约发行价格，不承诺未来公链 gas 免费。因此它不是把可转让 RTM 改成“荣誉”名称来继续承载原经济机制。

但这些限制不能证明合法性、身份真实性或事实真实性：

- **钱包不是身份**：EOA 签名证明密钥控制，不证明真实身份或签署权限；不支持 EIP-1271 合约钱包。不可转让 token 不能阻止出售整个钱包、私钥泄漏或胁迫控制。
- **摘要不是事实认证**：链下 helper 校验材料字节和审核记录，合约不读取证据文件、不验证 evidence digest 或贡献事实。审核者可能判断错误或造假；换贡献键重复提交仍需人工语义去重。
- **元数据去敏不等于匿名**：展示省略钱包和摘要，但 owner、事件及 contributionId 仍可公开地址与贡献关联；hash 不是匿名化或删除机制，撤销不擦除链上历史。
- **签名不等于全部隐私义务完成**：接收协议同意尚不能替代完整告知、处理依据、公开关联、保留与权利请求安排；撤销、申诉、错误纠正和遗失钱包的现实处置仍待设计。
- **有权限检查不等于生产密钥治理**：发行者与 owner 是信任点，owner 可轮换 issuer；未完成真实审核人认证、多方复核、密钥生命周期、事故响应及权力滥用防范。

[本地演示脚本](../../contracts/scripts/flower-demo.js)与协议 helper 限制 Hardhat 31337、无分叉。**这是演示执行边界，不是 Solidity 源码从技术上永远无法部署到其他网络的保证。** 未来如变更脚本、网络、使用者或发行安排，必须重新审批，不沿用本地演示结论。

### 3.3 展示已上线，不等于服务与资产已发布

[官网编辑源](../site/index.html#governance)合并当前边界与五类治理风险；根[发布入口](../../index.html)是单 HTML 展示。编辑源已经内联样式、脚本、SVG 和合成快照，[构建脚本](../../scripts/build_site.py)检查这些约束后按字节复制为根入口；现有[发布工作流](../../.github/workflows/pages.yml)只打包静态站点，[Jekyll 配置](../../_config.yml)排除研究目录。

依据 README 和发布清单，公开 GitHub Pages 展示站已上线；本次没有现场重验其可访问性。展示不启动研究后端，不调用模型，不收款，不连接钱包，不发交易，不发行 NFT，也不查询实时公链。两朵 Flower 图是同一个本地 token 的有效与撤销时点，不是两枚公网资产。

Pages 排除研究目录，只缩小展示站运行与发布范围，**不使公开 GitHub 源码、历史文案或仓库链接消失，也不是一揽子合规批准**。仓库推广入口仍有缺口，不称“宣传、配置和审查已全部完成”。

## 五、阻断性部署门禁与停线条件

### 5.1 按活动分开准入，不能“一次审查全部放行”

| 拟进入的活动 | 当前判断 | 必须先完成的门禁 |
|---|---|---|
| 继续阅读和展示现有合成研究 | 已有静态展示，不新增业务入口 | 持续核对宣传真实性、来源版本、公开字段与排除清单；任何新增功能重新评审 |
| 企业封闭试点、接收真实材料 | **尚未具备可核验的正式准入材料** | 经营责任、签字授权、合同/保密/数据安排、隔离、模型供应商与私密漏洞流程成文并签署；专业审查完成；数据最小化与资金切断得到验证 |
| 对外收费的可重复服务 | **尚未完成商业验证** | 在上述门禁外，完成限定试点交付、人工签收、成本/价格验证，落实正常开票纳税安排与持续回归责任；不靠 NFT 形成收费资格 |
| Flower 公网发行或商业接入 | **本地原型之外的范围未完成** | 完成专项法律、隐私、安全、真实审核、接收告知、撤销申诉、身份与密钥治理、实际网络与服务义务评审；不以网站已上线作为放行证据 |
| 真实资金接入、公开有偿挑战 | **不属于当前首期范围** | 另立项目审查和审批；资金责任及必要许可边界、参与与披露规则未清楚前不得开放 |

**需要正式文件，而不是口头认可**：合同至少界定服务和测试范围、目标与授权方、数据用途、模型处理、保密、成果权利、交付/验收分母、未解决发现、停止/应急、责任及争议处理。上述内容是待形成的审查输入，不声称现已有可签署模板。经营主体及授权代表的权利也须核实，不能以技术中的 `owner` 或钱包持有人代替法律上的客户代表。

### 5.2 任一触发即暂停相应活动

- 授权不清、授权人权限未经核验，或目标/时段/权限/数据范围变更未重新确认。
- 客户代码、资料、秘密或环境隔离失效；外部模型处理与数据去向尚未获确认。
- 原始证据无法独立复核、对照不能完成正常任务、目标可改真值/评分，或把错误、未触达和未支持计为通过。
- 真实资金路径、生产凭据或公网发行入口意外接入；商业部署出现 RTM、兑换、市场、收益或融资安排。
- Flower 缺接收同意、上下文/nonce/期限错误、审核或公开字段存在问题；出现销售、经济权益、转让或变相重分配需求。
- 宣传把研究验收、技术锁定、备案、口头建议或本报告解释成许可、合规保证、收益承诺或生产安全认证。

[2026-10-05 live.v3 对照报告](../../rsi4safety/payment_agents/evidence/VALIDATION10H_COMPARATIVE_2026-10-05.md)记录 L0 6 个确认发现、2 次晋级，L1 13 个模型层发现、1 次晋级；冻结验收通过但仍有 **12 个开放发现（L0 1、L1 11）**。L1 的 449 笔是授权内模拟落账，不是真实交易量、客户案例或法律合规证据。后续试点必须保留这些限制，不能借 Flower 认可或“验收通过”隐藏剩余风险。

## 六、专业法律审查需要哪些输入

建议把以下材料交给有相关经验的专业律师，记录审查日期、范围、事实假设、版本、意见、限制、未决项及复审条件；如需主管部门确认或手续，也应留下实际记录。导师、律师或其他人士的口头建议不等于正式意见或批准。

1. **主体与业务事实**：实际经营主体、服务对象与地区、部署地点、收费路径、交付内容；明确静态展示、企业评测、公众 AI 服务、奖励活动、NFT 发行是不同活动，不预设同一准入结论。
2. **正式协议材料**：拟定服务合同、目标方签字授权、保密与数据处理安排、成果/知识产权与发布条款；授权代表的权利证明。当前讨论稿只能作起草输入。
3. **技术与功能清单**：商业部署白名单、RTM 排除清单、接口与依赖、模拟资金路径、外网出口与实际模型处理；Flower 完整源码、网络选择、不可转让与撤销语义。
4. **数据与披露材料**：数据分类/流向/地域、模型供应商保留与转委托、访问权限、保留删除、未公开漏洞私密处置、拟公开字段、地址关联及无法擦除历史的告知。
5. **治理与审查材料**：贡献真实性和语义去重、身份/接收资格、签名同意、发行者与 owner 权限/密钥、撤销纠错申诉、钱包转卖与丢失风险、应急责任。
6. **经营及发布材料**：网站真实功能与文案、实际营销渠道、许可/备案适用问题、拟收费及税务安排；如开展奖励活动，另交预算、评审、防合谋、成果使用和支付规则。
7. **有限证据材料**：版本固定的研究报告、未覆盖项和开放发现、既有本地测试记录及失败路径；不得把局部通过率或合成审核记录作为生产认证。

## 八、推荐的真实对外描述

> REDTEAM 当前是智能体交易与支付安全的研究和产品验证项目，拟在企业书面授权、合成或经审查脱敏数据及隔离环境中，提供安全评测、整改复核与持续回归。已有限定真实模型实验和公开静态展示，仍有未解决发现，企业客户、收费与商业交付尚待验证。首期不接真实资金、不托管或代收代付，不以虚拟货币或 NFT 销售形成收入。独立的 REDTEAM Flower 是免费、不可转让且无经济权益的本地 NFT 原型，仅用合成材料演示，未公开发行或主网部署；历史可转让 RTM 源码仍保留为独立研究，不接当前商业路线。正式法律、隐私、发行与经营审查尚未完成。

不应使用“已完成国内合规”“获监管批准”“NFT/免费/不可转让天然合法”“口头认可即放行”“已开票纳税/已有客户收入”“已上线 NFT 市场”“完全不可交易”“链上证明真实身份或贡献”“验收通过即可生产上线”等表述。不能把研究成果说明改成金融宣传，也不能靠隐藏旧 RTM 身份获得新的安全感。
