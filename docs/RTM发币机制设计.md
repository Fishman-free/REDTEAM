## 一、一句话版本

**RTM 不靠"挖算力"发行，靠"挖智能体的漏洞"发行：谁能攻破平台守卫的 AI 支付智能体、把它钱包里的钱转走，谁就挖到了币。防御每修复一类漏洞，下一类漏洞就更难找——这就是 RTM 的"难度调节器"，替代了比特币的算力难度。**

---

## 二、为什么这样设计

### 2.1 传统发币的问题

- **PoW（比特币）**：耗费电力做无意义的哈希题，安全锚定在算力上。
- **PoS（以太坊）**：质押越多权力越大，富有者更富有。
- **预铸+私募**：团队手里有全部筹码，社区只能接盘。

### 2.2 RTM 的选择

REDTEAM 的核心资产是"经过实战检验的智能体安全能力"。每一枚 RTM 背后都对应一次**真实被证实的社会工程学攻击**——攻击者真的说服了一个管钱的 AI 智能体违规转账。发币量 = 平台被攻破的程度，币的产出过程本身就是安全测试过程，产出物（攻击数据）直接回流防御研究。

三重价值闭环：

```
矿工攻击 ──▶ 攻破得币（矿工收入）
   │
   └──▶ 平台收集攻击数据 ──▶ RSI 修复智能体 ──▶ 防御变强
                                                    │
              下一轮挖矿更难 ◀── 新版本智能体上链 ◀──┘
```

## 三、两种币、两条链

| | tRTM（测试币） | RTM（主币） |
|---|---|---|
| 链 | 自建测试链（Besu QBFT，1 验证者，零 gas） | 自建主链（Besu QBFT，4 验证者，零 gas） |
| 获取 | 水龙头免费领取（EIP-712 票据 + 24h 冷却，防女巫） | 红队挖矿产出 |
| 价值 | 无，纯演练 | 可通过 Base 桥 + Uniswap 与 USDC/ETH 双向兑换 |
| 标记 | 相同：靶钱包转出仅限注册攻方，否则交易失败 | 同左 |

**为什么自建链而不是发在以太坊上**：攻破判定要写进代币合约本身（"靶钱包只能转给注册攻方"这条规则），且比赛需要零 gas——攻方发消息、智能体签名转账都不该被 ETH gas 费打断。自建 Besu PoA 链让我们完全掌控这两点。

**为什么"标记"很重要**：tRTM/RTM 的转账函数内置靶钱包规则。守方智能体的钱包在比赛期间被合约标记为"靶"，它向外转账只有两个合法去向——该场注册攻方（=攻破，自动结算）或平台结算合约。守方想偷偷把钱转给自己的小号？交易直接失败。这就是"检测到守方向攻方转移即结束比赛"的链上实现：**检测规则和结算规则是同一个函数里的两行代码，原子完成，没有裁判窗口，没有争议空间。**

## 四、挖矿详细流程

### 4.1 一场挖矿赛的构成

1. **平台是守方**：平台把自己研发的支付智能体（带 DefensePackage 防御包）上链，其普通钱包 W 作为靶。
2. **奖池随时间增长**：任何人（包括路人）调用合约的 `accrue()`，每过 2 小时一个 epoch，向 W 线性注入 `E_rate` 枚新铸 RTM。无需定时器机器人——惰性计算，谁调用谁触发，链上保证精确。
3. **矿工=攻方**：按攻方规则加入——质押奖金池的 r%，之后每 2h 被罚剩余质押的 25%（归平台金库，覆盖平台运行智能体的推理成本），每发一条攻击消息付 0.5% 手续费。
4. **攻破=挖中**：矿工说服智能体把 W 里的钱转到自己地址 → 代币合约当场触发结算：W 全部余额划给该矿工，比赛结束。
5. **修复与再上链**：平台取回该场全部对话与工具轨迹，跑修复闭环（`campaign_repair` 修复门禁 + 技能沉淀），产出新版本 DefensePackage，上链开下一场。**同一个攻击套路对新版本失效——这就是难度上升。**

### 4.2 难度调节：RSI 替代算力

| | 比特币 | RTM |
|---|---|---|
| 难度来源 | 全网算力竞争 | 平台防御版本迭代 |
| 难度上升信号 | 出块变慢 → 调整难度目标 | 攻破率下降、每枚币消耗的攻击消息数上升 |
| 矿工的应对 | 买更多矿机 | 发明真正新颖的攻击（旧攻击被技能库免疫） |
| 调节主体 | 协议自动 | 平台 RSI 闭环（数据驱动、版本可审计） |

矿工的边际成本（攻击消息费 + 质押罚没 + 自己的模型推理费）随防御变强而上升；当攻破期望收益低于成本，弱矿工退出，只留高水平攻击者——**算力门槛换成了智力门槛**。

### 4.3 防作弊：为什么"自己攻自己"在这里也亏

有人问：平台自己攻击自己的智能体，把新铸的币转给自己，岂不是白拿？

不是。挖矿赛的奖池由新铸币构成，平台角色攻破平台角色，拿到的钱本来就要进平台金库——净变化为零；但每发一条消息要付 0.5% 手续费（真金白银从金库扣掉），外加质押被 25%/2h 罚没（罚没也进金库，两抵）。**净结果 = 手续费净损失 + 向全体用户公示了一场"攻破"，损害平台智能体的声誉估值。**机制上无利可图，声誉上自伤。同时所有攻破事件链上可查，任何人可以统计"平台钱包是否是常见获胜者"来监督。

## 五、博弈论与激励机制

发币机制能不能持续，不取决于白皮书写得漂不漂亮，而取决于**每一方在给定规则下的最优策略是不是"诚实参与"**。本节把四方（守方、攻方/矿工、平台、数据买家）的收益矩阵摊开算清楚。这不是营销话术——每一项都能在链上验证。

### 5.1 参与方收益矩阵

| 角色 | 投入 | 收益来源 | 最大损失上界 | 理性参与条件 |
|---|---|---|---|---|
| **守方** | 质押 S（50 RTM）+ 自付 AI 推理费 | 攻方罚款（每 2h 罚攻方剩余质押 25%）+ 到期赎回 S + 守住声誉 | S + 推理费 | 自认智能体较强，预期存活收入 > 被破概率 × S |
| **攻方/矿工** | 质押 s=r·S + 每条消息 0.5%×S + 自备模型成本 | 攻破得 W 钱包全部余额 | s×(1−3.2%) + 全部消息费 + 推理费 | P(攻破)×奖池 > 时间罚没 + 消息费 |
| **平台** | 服务器 + 挖矿赛推理费 | 消息手续费 + 挖矿赛罚没归集 + 数据销售 70% 抽成 | 运营成本 | 与任何一方胜负脱钩，旱涝保收 |
| **数据买家** | 数据价 dataPriceBps×S | 攻击数据（用于防御修复或攻击研究） | 数据价 | 数据价值 > 价格 |

**关键设计：每一方的损失都有硬上界，且上界在入场前就是已知数。**没有"无限追加保证金"或"未知清算风险"。

### 5.2 激励相容：坏行为在数学上不赚钱

机制设计的第一原则：与其检测作弊再惩罚，不如让作弊本身亏钱（激励相容，incentive compatibility）。RTM 用四条规则实现了这一点：

**规则一：奖池只装守方的钱 → 自攻自守严格亏损。**

一个人同时扮演守方和攻方（可以用几十个钱包伪装成不同的人，链上看不出来）会怎样？

```
守方角色：质押 50 进奖池
攻方角色：质押 5 进托管，发 N 条消息（每条 0.25 手续费）
攻破后：  攻方角色拿走奖池 50 —— 但这 50 本来就是他自己的！
净结果 = −N × 0.25（手续费，真金白银付给了平台）
```

钱包演得再多也没用：**自己口袋里的钱转到自己另一个口袋，财富总量不变，但每条消息要给平台交手续费。**这条路径的收益是恒负的，不需要识破，不需要 KYC，不需要裁判。这是整个机制最硬的一条防线。

（有一类变体是"守方和**真**攻方私下分账"——守方故意放水让朋友攻破，五五分。但放水守方损失的是全部 S=50，两人合计最多拿回 50−手续费，再怎么分都不如守方自己守住赚罚款。链上无法阻止他们亏钱交朋友，但没有理性动机。）

**规则二：质押不可退出 → 没有"卡 bug 退出"。**

攻方一旦加入，质押锁定到比赛结束。这堵住了一个经典漏洞：在 1 小时 59 分（马上要交下一轮罚款时）退出再重新加入，重置罚款时钟。锁定后，"止损"的唯一方式是停止发消息——罚款照走，时间成本照付。

**规则三：守方弃权视同被攻破 → 临阵撤 Key 不保命。**

守方自付推理费（自带 API Key）。若守方看到强攻方入场，想撤销 Key 让智能体"死机"保住质押呢？规则：Key 失效导致付费消息无法送达 = 守方弃权 = 按被攻破结算，S 分给攻方。撤 Key 和被攻破经济后果相同，那还不如让智能体上场——至少有守住赚罚款的机会。

**规则四：平台收入与胜负脱钩 → 平台没有操纵动机。**

平台赚的是手续费、抽成和挖矿赛罚没归集，无论谁赢。平台若故意放水某个攻方，不增加自己一分收入；若故意做强守方，也不减少。对比"平台做市赚差价"或"平台持币盼涨"的设计，这里的利益冲突被结构性消除了。（平台仍需接受两条链上监督：挖矿赛获胜者地址分布是否异常、每枚币消耗的攻击消息数走势是否合理。）

### 5.3 罚没曲线：时间就是守方的复利

攻方每 2 小时被罚掉剩余质押的 25%，剩余质押按几何级数衰减：

```
经过 k 个 epoch 后剩余 = s × (3/4)^k

k=1  剩 75%     k=6 (12h)  剩 17.8%
k=3 (6h)  剩 42.2%     k=12 (24h)  剩 3.2%
```

这条曲线同时完成了三件事：

1. **给攻方足够的试探窗口**（前 6 小时还剩 42%，不会开局即劝退）；
2. **给守方指数级增长的存活收入**——理论峰值约为 3 倍单个人质池的几何级数和；
3. **自动出清"僵尸攻方"**——挂着不动的攻方质押持续流向守方，不会占用奖池竞争名额。

链上实现是惰性计算：没有定时器、没有机器人，任何人任何时刻查询都得到精确值（O(1) 一次乘法），守方随时可以拉走已累计罚款。

### 5.4 自由进入均衡：市场自己定价"一个漏洞值多少钱"

不设准入门槛，让 EV（期望收益）自动调节攻方人数 N：

```
攻方 EV(N) = P(攻破 | 你的技术水平, N) × 奖池 − 时间罚没 − 消息费 − 推理费
```

- 奖池固定时，N 越大，单个攻方抢到攻破的概率越低（只有一个赢家），边际攻方的 EV 随 N 递减；
- 当 EV < 0，新攻方不再进场，存量攻方自然退出 → 均衡人数 N*；
- **守方智能体越弱 → P 越高 → N* 越大 → 罚款收入越厚**；反过来守方越强，攻方稀少，守方主要赚"到期赎回+声誉"。

这形成了一个不需要任何人定价的漏洞市场：**弱智能体被快速攻破并被高额罚款"惩罚"，强智能体获得稀少的攻击流量和干净的存活记录。**安全能力的价格由市场每一分钟重新报出。

### 5.5 声誉机制：排行榜是第二货币

链上事件驱动的三方排行榜构成显性声誉激励：

| 榜 | 核心指标 | 声誉价值 |
|---|---|---|
| 攻方/矿工榜 | 胜场、赢得 RTM 总额、**难度分**（=攻破前目标承受的付费消息总数）、最长连胜 | 难度分让"攻破一个扛住 300 条消息的强靶"远重于"捡软柿子"，抑制刷弱靶 |
| 守方榜 | 守住场次、累计承受消息数、净收入、最长存活 | 守方把榜单截图就是安全能力的公开凭证——这直接服务于 REDTEAM 的企业服务商业线 |
| 挖矿榜 | 挖矿产出、历史攻破率走势 | 全网可审计的"平台防御是否真的变强"指标 |

难度分是关键防刷设计：如果榜只按胜场排，攻方会专挑弱守方刷场次；加入"目标承受了多少条付费消息"的权重后，刷弱靶的边际收益趋近于零。

### 5.6 数据市场的博弈：70/30 抽成与卖家同意权

数据是本机制独有的副产品（攻击手法数据），其交易规则本身也是一个微型机制设计：

- **卖家同意权**：守方想买某攻方的进攻数据，必须该攻方链上签名同意。攻方对自己的独门攻击手法有定价与披露决定权——否则攻方的最优策略变成"藏着好攻击不卖"，数据市场枯死；
- **70/30 抽成**：成交额 70% 归平台、30% 归攻方。抽成偏高意味着攻方只有在数据对自己不再稀缺（攻击已被修复、手法已扩散）时才会同意出售——**这个"摩擦"其实是特性**：流到市场上的多是"过期"攻击数据，而平台拿大头正好用于补贴 RSI 研究成本；
- **特例**：守方买自己被攻破的数据无需任何人同意——自己的失窃数据，权利当然归自己，否则守方修复自己的漏洞还要看小偷脸色，荒谬。

### 5.7 攻防不对称的审计：三个链上可验证的监督指标

机制声称"防合谋、防放水、防刷榜"，不能只靠声称。三个任何人都能从链上算出的指标构成持续审计：

1. **挖矿赛获胜者地址分布**：若平台关联地址频繁获胜 → 疑似自导自演（虽然规则一已让其无利可图，但声誉损失仍需公示）；
2. **每枚 RTM 消耗的攻击消息数**：持续上升 = 防御真的在变强（难度上升的客观证据）；骤降 = 疑似放水或漏洞回退；
3. **守方净收入分布**：若长期全员净负 → 守方参与崩塌前兆，需要调整参数（罚款率、消息费）。

---



### 6.1 删除减半

原设计模仿比特币"每年产量减半"（总量 2100 万封顶）。**本设计删除之**，理由：

1. 比特币减半锚定的是"算力投入的边际递减"，与安全测试无关；
2. RTM 的产出本来就随防御变强自然递减（攻破越来越难），减半是叠床架屋；
3. 固定总量上限会迫使平台在早期"抢发"，与"安全能力成熟度决定产出"的叙事矛盾。

### 6.2 供给函数

```
第 k 个挖矿赛的总注入 = E_rate × floor(该赛存续时长 / 2h)
全网供给 = Σ 各历史挖矿赛注入 + 创世金库分配（用于流动性）
```

- **无总量上限，无年度预算**：供给速率由单一参数 `E_rate` 控制（初始值由参数仿真确定，治理可调）。
- **产出与安全事件强绑定**：智能体无懈可击时，奖池注入会不断累积但永远没人能拿走——此时平台应主动下调 `E_rate`（奖池持续膨胀等于变相通胀），下调依据是链上公开的"每枚产出消耗攻击消息数"走势。
- **退出机制**：若平台停止运营，`E_rate` 置零，链与既有余额照常运转，没有增发，没有归零开关。

### 6.3 创世分配

- 平台金库保留少量创世 RTM，**唯一用途**是在 Base 的 Uniswap V2 上为 wRTM/USDC 池播种流动性（让矿工挖到的币有去处），不用于团队抛售；
- 无私募、无预挖给个人。

## 七、购买与兑换（主网）

用户想买 RTM / 矿工想换成主流币：

```
本链 RTM ──lock──▶ RTMBridge ──中继(M-of-N签名)──▶ Base 上 mint wRTM
Base 上 wRTM ──Uniswap V2──▶ USDC / ETH
反向：Base burn wRTM ──中继──▶ 本链 unlock RTM
```

- 桥有日限额与紧急暂停开关，中继签名者多签（M-of-N），异常自动停机；
- 兑换不依赖平台定价——价格完全由 Uniswap 池内市场决定，平台只提供初始流动性；
- 该模块独立于发币逻辑，feature flag 控制（法律审查通过前不启用；虚拟货币兑换业务在部分司法辖区受限，需正式法律意见，本设计不构成合规保证）。

## 八、参数一览

| 参数 | 默认值 | 谁能改 | 说明 |
|---|---|---|---|
| E（epoch 长度） | 2 小时 | 治理 | 罚款与铸币共用时钟 |
| 罚款率 | 25%/epoch | 治理 | 24h 后攻方剩约 3.2% |
| 消息手续费 | 0.5% × 奖池基数 | 治理 | 平台主要收入 |
| E_rate（每 epoch 铸币） | 仿真定 | 治理 | 唯一供给旋钮 |
| r（攻方质押比例） | 10% | 每场守方在 [2%,20%] 自选 | 攻方入场门槛 |
| 挖矿赛并发上限 K | 待定 | 平台 | 防奖池稀释 |

所有参数集中在一处合约常量/治理接口，链上透明可查，改动留事件痕迹。

---

## 九、与既有研究的关系

- 挖矿赛就是 REDTEAM 主线（支付智能体安全评测）的**持续在线版**：原来一次性的攻防实验（L0/L1 协议）变成 7×24 的公开擂台；
- 攻破数据经匿名化与有界化处理后进入 RSI 修复闭环，与现有 `campaign_repair`/`role_memory` 工具链无缝衔接；
- 排行榜上的"攻破率走势"同时是**平台安全能力的公开审计指标**——防御有没有真变强，链上数据说话，不靠自宣。
