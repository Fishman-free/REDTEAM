# RTM 发币机制设计

- 日期：2026-10-27
- 状态：定稿（随主规格 `docs/superpowers/specs/2026-10-27-rtm-redteam-game-design.md` 一起生效；2026-10-27 挖矿层修订：固定 1 RTM + 数据同意）
- 读者：项目成员、合作方与审查方

---

## 一、一句话版本

**RTM 不靠"挖算力"发行，靠"挖智能体的漏洞"发行：用户攻防层是守方质押的零和竞技；平台挖矿层是事件驱动发行——每次成功攻破平台守卫的 AI 支付智能体，矿工固定获得 1 RTM。没有按时间/epoch 的线性发行；防御每修复一类漏洞，下一个版本更难攻破，这就是 RTM 的"难度调节器"，替代比特币的算力难度。**

---

## 二、为什么这样设计

### 2.1 传统发币的问题

- **PoW（比特币）**：耗费电力做无意义的哈希题，安全锚定在算力上。
- **PoS（以太坊）**：质押越多权力越大，富有者更富有。
- **预铸+私募**：团队手里有全部筹码，社区只能接盘。

### 2.2 RTM 的选择

REDTEAM 的核心资产是"经过实战检验的智能体安全能力"。每一枚挖矿产出的 RTM 背后都对应一次**真实被证实的社会工程学攻击**——攻击者真的说服了一个管钱的 AI 智能体违规转账。**每次成功攻破固定奖励 1 RTM**：供给按成功攻破次数离散增长，不按时间膨胀。产出过程本身就是安全测试过程，产出物（攻击数据）强制回流防御研究（挖矿层）或经加入时同意进入数据市场（用户层）。

三重价值闭环：

```
矿工攻击 ──▶ 成功攻破固定 1 RTM（矿工收入）
   │
   └──▶ 平台强制留存矿工数据 ──▶ RSI 修复 ──▶ 新版本/新 defenseHash
                                                    │
              下一轮挖矿更难 ◀── 新版本智能体上链 ◀──┘
```

### 2.3 两层分离（本次修订核心）

| 维度 | 用户攻防层 | 平台挖矿层 |
|---|---|---|
| 守方 | 用户（自带智能体） | 平台自有智能体 |
| 攻方 | 普通攻方，质押 s = r·S | 矿工，无质押 |
| 奖池 | 守方质押 S | 平台从 Treasury 预打款 1 RTM 到新 W；Treasury 工作资金共 3 RTM（含活跃 W 预打款） |
| 发行 | 无增发 | 每次成功攻破 +1 RTM |
| 罚款 | 25%/2h，归守方 | 无罚款、无剩余质押提款 |
| 数据 | join 时 opt-in，可售 | 强制留存，仅 RSI，不售 |
| 经济性质 | 零和 + 手续费/推理费 | 事件驱动增发，非零和 |
| 生命周期 | 到期/攻破/弃权 | 攻破或平台退役，立即停赛 |

**为什么必须分开**：用户层奖池是守方质押，罚款与奖金在参与方之间转移，满足零和恒等式；挖矿层奖池是平台从 Treasury 工作资金预打款到 W 的 1 RTM，成功攻破时补铸，属于净增发。把两层混在一起会同时算错发行量、罚款与平台风险；本设计从合约、参数、数据与账本四个层面分开。

## 三、两种币、两条链

| | tRTM（测试币） | RTM（主币） |
|---|---|---|
| 链 | 自建测试链（Besu QBFT，1 验证者，零 gas） | 自建主链（Besu QBFT，4 验证者，零 gas） |
| 获取 | 水龙头免费领取（EIP-712 票据 + 24h 冷却，防女巫） | 挖矿成功攻破固定 1 RTM |
| 价值 | 无，纯演练 | 可通过 Base 桥 + Uniswap 与 USDC/ETH 双向兑换 |
| 标记 | 相同：靶钱包转出仅限注册攻方，否则交易失败 | 同左 |

**tRTM 的用途**：测试网攻方/矿工需要少量 tRTM 支付消息费（普通赛 0.5%×S；挖矿赛 0.005 RTM/条）；矿工没有质押，不能靠"提走剩余质押"回收成本，停止攻击只损失已付消息费与模型推理费。

**为什么自建链而不是发在以太坊上**：攻破判定要写进代币合约本身（"靶钱包只能转给注册攻方"这条规则），且比赛需要零 gas——攻方发消息、智能体签名转账都不该被 ETH gas 费打断。自建 Besu PoA 链让我们完全掌控这两点。

**为什么"标记"很重要**：tRTM/RTM 的转账函数内置靶钱包规则。守方智能体的钱包在比赛期间被合约标记为"靶"，它向外转账只有两个合法去向——该场注册攻方（=攻破，自动结算）或平台结算合约。守方想偷偷把钱转给自己的小号？交易直接失败。这就是"检测到守方向攻方转移即结束比赛"的链上实现：**检测规则和结算规则是同一个函数里的两行代码，原子完成，没有裁判窗口，没有争议空间。**

普通赛的 W 预置守方质押 S；挖矿赛的 W 由平台先从 Treasury `withdraw` 预打款 **1 RTM** 固定奖池，没有随时间增长的余额。

## 四、挖矿详细流程

### 4.1 一场挖矿赛的构成

1. **平台是守方**：平台把自己研发的支付智能体（带 DefensePackage 防御包）上链，其普通钱包 W 作为靶；每个防御版本对应一个 `defenseHash`。每场挖矿赛必须使用**全新 W**（未注册为靶、从未受控、预打款前余额为 0），旧 W 永久受控、不可复用。
2. **奖池固定 1 RTM**：平台先为每场生成全新 W，由 **Treasury owner/多签/平台金库服务**（不是 operator）调用 `Treasury.withdraw(rtm, W, 1 RTM)` 预打款；随后 operator 只调用 `createMiningContest(wallet, defenseHash)`，合约只校验 W 余额恰为 1 RTM。没有 `accrue()`，没有每 2 小时增长，没有铸币速率参数；**不消耗 Treasury allowance**。预打款前先校验 hash/K；若 create revert，1 RTM 留在新 W，用 W 私钥/owner 转回 Treasury。Treasury 工作资金共 3 RTM（含活跃 W 预打款，不含手续费/退款准备金），不按“余额低于 3”补款。
3. **矿工无质押**：`joinMining(id, acceptData)` 加入，`acceptData` 必须为 true（数据强制留存，仅用于 RSI）；每个地址一次，最多 50 人。矿工不需要 approve RTM，没有罚款，没有 `withdrawStake`，没有 `collectPenalties`。
4. **消息费 0.005 RTM/条**：每条攻击消息付 `1 RTM × 0.5% = 0.005 RTM` 给 Treasury。矿工需要少量 tRTM，测试网可从水龙头领取。
5. **攻破=挖中**：矿工说服智能体向自己转账 → RTMToken 只把本次 `value` 转给该矿工并回调 `Arena.onBreach`；Arena 把 W 剩余余额 `controllerTransfer` 给 winner 完成扫尾（合计 W 的全部余额，正常为 1 RTM）。Arena 立即结束本场、把 `defenseHash` 标记 retired，并向 Treasury 补铸 1 RTM 以补偿平台预打款。净增发 = 1 RTM/次成功攻破。
6. **停服、修复与再上链**：runner 立即停止该赛；平台导出全部矿工数据（消息、回复、工具轨迹、snapshot）跑修复闭环（`campaign_repair` 修复门禁 + 技能沉淀），产出新版本 DefensePackage；`benchmark` 生成新 digest/新 `defenseHash`，再开新挖矿赛。**同一攻击套路对新版本失效——这就是难度上升。**
7. **未攻破退役**：平台主动停止或 fault 时，W 的预置奖池余额（正常为 1 RTM）退回 Treasury，不铸造；`defenseHash` 同样永久 retired。必须换新 hash 才能再开，链上没有冷却期。

### 4.2 难度调节：RSI 替代算力

| | 比特币 | RTM |
|---|---|---|
| 难度来源 | 全网算力竞争 | 平台防御版本迭代 |
| 难度上升信号 | 出块变慢 → 调整难度目标 | 攻破率下降、每枚 RTM 消耗的攻击消息数上升 |
| 矿工的应对 | 买更多矿机 | 发明真正新颖的攻击（旧攻击被技能库免疫） |
| 调节主体 | 协议自动 | 平台 RSI 闭环（数据驱动、版本可审计） |

矿工的边际成本 = 攻击消息费（0.005 RTM/条）+ 自己的模型推理费；**没有质押罚没**。防御变强时，攻破概率下降，期望收益低于成本，弱矿工退出，只留高水平攻击者——**算力门槛换成了智力门槛**。难度不再靠任何时间发行参数调节。

### 4.3 防作弊：普通层自攻自守严格亏损；挖矿层平台自挖是增发风险

**普通层（用户攻防）**：一个人同时扮演守方和攻方（可以用几十个钱包伪装）会怎样？

```
守方角色：质押 50 进奖池
攻方角色：质押 5 进托管，发 N 条消息（每条 0.25 手续费）
攻破后：  攻方角色拿走奖池 50 —— 但这 50 本来就是他自己的！
净结果 = −N × 0.25（手续费，真金白银付给了平台）
```

钱包演得再多也没用：**自己口袋里的钱转到自己另一个口袋，财富总量不变，但每条消息要给平台交手续费。**这条路径的收益恒负，是用户层最硬的防线。

**挖矿层（平台挖矿）不同**：平台如果控制矿工地址攻击自己的挖矿赛，矿工赢得 Treasury 预打款的 1 RTM，Arena 再补铸 1 RTM 回 Treasury，手续费在平台内部转移。结果不是普通层的参与方内部转移，而是 **平台净增 +1 RTM、全网净增发 +1 RTM**。链上无法完全禁止，只能靠"不自我挖矿"运营政策、独立地址审计、K=3 并发上限与 hash 退役降低风险；所有攻破事件链上可查，任何人都能统计异常获胜地址。**普通层的"自攻自守严格亏损"仍然成立，不能套用到挖矿层。**

外部矿工无法自己开一场挖矿赛当守方（平台是唯一守方），也没有质押可玩"自攻自守"；矿工获得 1 RTM 的唯一方式是攻破平台智能体，否则只损失消息费与推理费。

## 五、博弈论与激励机制

发币机制能不能持续，取决于**每一方在给定规则下的最优策略是不是"诚实参与"**。本节把用户层守方/攻方、挖矿层矿工、平台、数据买家的收益摊开算清楚。每一项都能在链上验证。

### 5.1 参与方收益矩阵

| 角色 | 投入 | 收益来源 | 最大损失上界 | 理性参与条件 |
|---|---|---|---|---|
| **用户层守方** | 质押 S（50 RTM）+ 自付 AI 推理费 | 攻方罚款（每 2h 罚攻方剩余质押 25%）+ 到期赎回 S + 守住声誉 | S + 推理费 | 真实强度高于市场预期：罚款收入 > 被破概率 × S |
| **用户层攻方** | 质押 s=r·S + 每条消息 0.5%×S + 自备模型成本 | 攻破得 W 钱包余额；join 同意数据者另有 30% 数据分成 | s + 全部消息费 + 推理费 | P(攻破)×奖池 + 数据收入 > 时间罚没 + 消息费 + 推理费 |
| **挖矿层矿工** | **无质押**；0.005 RTM/条消息费 + 自备模型成本；数据强制留存 | 成功攻破固定 1 RTM | 消息费 + 推理费（无质押罚没） | P(攻破)×1 RTM > 消息费 + 推理费 |
| **平台（普通层）** | 服务器 + 运营成本 | 用户层消息费 + 数据销售 70% | 运营成本 | 与普通层胜负脱钩 |
| **平台（挖矿消息费）** | Treasury 工作资金共 3 RTM（含活跃 W 预打款）、推理/RSI 成本 | **0.005 RTM × 矿工消息数**；外部矿工攻破时固定 1 RTM 奖励净额为 0（预打款 1 → 补铸 1）；平台自挖时净增 +1 RTM | 推理/RSI 成本；自挖增发风险 | 挖矿消息费收入 > 推理/RSI 成本 |
| **数据买家** | 数据价 dataPriceBps×S 或 attackerDataPrice | 攻击数据（用于防御修复或攻击研究） | 数据价 | 数据价值 > 价格 |

**关键设计：每一方的损失都有硬上界，且上界在入场前就是已知数。**矿工没有质押，最大损失就是已付消息费 + 推理费；普通攻方最大损失是 s + 消息费 + 推理费；守方最大损失是 S + 推理费。

### 5.2 激励相容：普通层坏行为在数学上不赚钱，挖矿层需运营约束

**规则一（普通层）：奖池只装守方的钱 → 自攻自守严格亏损。**

```
守方：质押 50 进奖池
攻方：质押 5 进托管，发 N 条消息（每条 0.25 手续费）
攻破：攻方拿回奖池 50 —— 但这 50 本来就是自己的
净结果 = −N × 0.25
```

这条路径收益恒负，不需要识破，不需要 KYC，不需要裁判。挖矿层没有这条"内生防线"：矿工无质押，平台自挖会净增发 1 RTM，必须靠不自我挖矿政策、审计与 K=3 上限约束（见 4.3）。

**规则二（普通层）：质押不可退出 → 没有"卡 bug 退出"。** 普通攻方一旦加入，质押锁定到比赛结束；"止损"的唯一方式是停止发消息，罚款照走。挖矿层矿工无质押，随时可以停止攻击，只损失已付消息费与推理费——这是有意的低门槛设计。

**规则三（普通层）：守方弃权视同被攻破 → 临阵撤 Key 不保命。** Key 失效导致付费消息无法送达 = 守方弃权 = 按被攻破结算，S 分给攻方。挖矿层由平台自持，平台主动停止走 `retireMining`：退回 1 RTM、不铸造、hash 退役，不存在"弃权分 S"。

**规则四：平台收入与胜负脱钩（普通层）；挖矿层靠审计与政策。** 普通层平台赚手续费与数据抽成，无论谁赢；放水不增加收入。挖矿层平台是发行方，若自我挖矿会净增发 1 RTM，不能声称"平台天然中立"；缓解是运营政策、独立地址审计、K=3 上限与链上公示。用户层与挖矿层必须分开评估。

### 5.3 罚没曲线：时间就是普通层守方的复利（挖矿层无罚款）

普通攻方每 2 小时被罚掉剩余质押的 25%，剩余质押按几何级数衰减：

```
经过 k 个 epoch 后剩余 = s × (3/4)^k

k=1  剩 75%     k=6 (12h)  剩 17.8%
k=3 (6h)  剩 42.2%     k=12 (24h)  剩 3.2%
```

这条曲线给普通攻方足够的试探窗口，同时给守方指数增长的存活收入，并自动出清"僵尸攻方"。链上实现是惰性计算：没有定时器、没有机器人，任何人任何时刻查询都得到精确值，守方随时可以拉走已累计罚款。

**挖矿层没有罚款、没有质押、没有剩余质押提款**：矿工成本只有 0.005 RTM/条消息费与模型推理费。不要把这套罚没曲线套到挖矿赛上。

### 5.4 自由进入均衡：普通层零和，挖矿层事件驱动

**普通层**不设准入门槛，让 EV 自动调节攻方人数 N：

```
攻方 EV(N) = P(攻破 | 技术水平, N) × 奖池 − 时间罚没 − 消息费 − 推理费
```

奖池固定时，N 越大，单个攻方抢到攻破的概率越低；EV < 0 时新攻方不再进场，形成均衡人数 N*。奖池只装守方质押、罚款与奖金都是参与方之间的转移，因此存在**零和恒等式**：

```
EV_守 + ΣEV_攻 = −(消息费 + 推理费)
```

对称信息下攻守**不可能同时正 EV**。机制靠技能分化运转：真实强度高于市场预期的守方（p_def < p_market）赚取正 EV；低于预期的守方亏损并退出。排行榜与历史存活记录让 p_market 逐步收敛。

**挖矿层**不是零和：矿工收益来自新铸币。矿工 EV 近似为：

```
矿工 EV = P(攻破) × 1 RTM − 0.005 × 消息条数 − 推理费
```

当 EV < 0，弱矿工退出；当版本被攻破，平台立即停赛并换新版本，P(攻破) 下降。挖矿层的发行量只由成功攻破次数决定，不由时间或参与人数决定；平台用 Treasury 工作资金（共 3 RTM，含活跃 W 预打款）逐场预打款，收入为 0.005 RTM × 矿工消息数，需扣除推理/RSI 成本。

### 5.5 声誉机制：排行榜是第二货币

链上事件驱动的三方排行榜构成显性声誉激励：

| 榜 | 核心指标 | 声誉价值 |
|---|---|---|
| 攻方/矿工榜 | 普通攻方：胜场、赢得 RTM、**难度分**（=攻破前目标承受的付费消息总数）、最长连胜；矿工：成功攻破次数、累计固定 1 RTM 奖励、难度分 | 难度分让"攻破一个扛住 300 条消息的强靶"远重于"捡软柿子"，抑制刷弱靶 |
| 守方榜 | 守住场次、累计承受消息数、净收入、最长存活 | 守方把榜单截图就是安全能力的公开凭证——这直接服务于 REDTEAM 的企业服务商业线 |
| 挖矿榜 | 成功攻破次数、累计固定奖励、历史攻破率、当前活跃版本/hash | 全网可审计的"平台防御是否真的变强"指标；不展示随时间累积的奖池 |

难度分是关键防刷设计：如果榜只按胜场排，攻方会专挑弱守方刷场次；加入"目标承受了多少条付费消息"的权重后，刷弱靶的边际收益趋近于零。

### 5.6 数据市场的博弈：加入时一次性同意 + 70/30 抽成

数据是本机制独有的副产品（攻击手法数据），其交易规则本身也是一个微型机制设计：

- **普通攻方加入时一次性 opt-in**：`join(..., dataConsent)` 决定平台能否持久化其攻击数据。`true` 才落盘、才进入数据集、才可由守方赛后购买；`false` 只做内存处理，不落盘、不进入数据集、不可售。同意不可撤回，链上记录事件供审计。
- **守方赛后决定买不买**：守方买自己的数据无需攻击者同意（自己的失窃数据）；买某攻方数据时，`DataMarket` 读取 `Arena.dataConsent`，只有该攻方 join 时同意才可成交，否则 revert `NotConsented`。没有 `approveSale`/`saleApproved`/逐买家授权——同意是参与时的属性，不是赛后逐笔谈判。
- **70/30 抽成**：成交额 70% 归平台（Treasury）、30% 归数据提供方。对普通攻方数据，30% 归该攻方；对守方自有数据，30% 退回守方（净付 70%）。例如 `attackerDataPrice=1 RTM` 时平台 0.7、攻方 0.3；`buyOwn` 价格 10%×S=5 RTM 时平台 3.5、守方退回 1.5。
- **数据集分层交付**：数据集根覆盖"守方自有数据 + 已同意攻方数据"，但 `buyOwn` 只交付守方自有数据，`buyFromAttacker` 只交付该攻方数据；买一种不会自动获得另一种。
- **挖矿数据强制但不售**：矿工加入即同意数据留存，平台保存全部消息/回复/工具轨迹，仅用于 RSI，不进入 DataMarket、不对外出售。`publish` 只允许普通赛，mining 一律拒绝。

为什么不做逐次卖家同意：用户明确选择"加入时一次性选择"；这避免赛后每笔交易都要卖家签名、降低数据市场摩擦，同时用链上 consent 保证可审计。代价是攻方不能在赛后改变主意——所以 UI/条款必须在 join 前明示。

### 5.7 攻防不对称的审计：四个链上可验证的监督指标

机制声称"防合谋、防放水、防刷榜"，不能只靠声称。以下指标任何人都能从链上算出：

1. **挖矿赛获胜者地址分布**：若平台关联地址频繁获胜 → 疑似自导自演；在挖矿层这不只是声誉问题，而是 **+1 RTM 净增发**，必须公开审计。
2. **每枚 RTM 消耗的攻击消息数**：持续上升 = 防御真的在变强（难度上升的客观证据）；骤降 = 疑似放水或漏洞回退。
3. **守方净收入分布**：若长期全员净负 → 普通层参与崩塌前兆，需要调整罚款率/消息费。
4. **Treasury 工作资金/预打款/补铸/退回对账**：挖矿工作资金不变量为 `Treasury 工作资金余额 + Σ活跃 W 预打款 = 3 RTM`（不含手续费/退款准备金）；3 场活跃时 Treasury 余额可为 0，不按余额补款。每场创建前应有 1 RTM 从 Treasury 预打款到新 W；成功攻破补铸 1 RTM、未攻破退回 W 余额。Treasury 固定奖励逐场净额为零；`refundAllowance` 只是权限、不是独立资金，退款从同一余额扣且仅用已收手续费。

## 六、供给、分配与"减半"

### 6.1 删除减半，也删除时间线性发行

原设计模仿比特币"每年产量减半"（总量 2100 万封顶）。**本设计删除之**，理由：

1. 比特币减半锚定的是"算力投入的边际递减"，与安全测试无关；
2. RTM 的产出本来就随防御变强自然递减（攻破越来越难），减半是叠床架屋；
3. 固定总量上限会迫使平台在早期"抢发"，与"安全能力成熟度决定产出"的叙事矛盾。

同时删除上一版的**时间线性挖矿发行**：不再有 `accrue`、`E_rate`、`miningRate`、`miningMinted`、`MAX_MINING_RATE`，也没有"每 2h 铸多少"、"每个 epoch 注入多少"的规则。供给不由时间驱动，只由成功攻破这个离散事件驱动。

### 6.2 供给函数

```
全网供给 = 创世/测试网注水 + 成功攻破次数 × 1 RTM
```

- **事件驱动，不是时间驱动**：只有矿工真的攻破平台智能体，才新增 1 RTM；未攻破不增发。时间 t 不进入供给公式。
- **无总量上限、无年度预算、无减半、无时间发行速率**：但也不会"躺赚通胀"——没有攻破就没有新币。
- **逐场 Treasury 固定奖励净额为零**：挖矿工作资金（不含手续费/退款准备金）满足 `Treasury 工作资金余额 + Σ活跃 W 预打款 = 3 RTM`；3 场活跃时 Treasury 工作资金余额可为 0，不按“余额低于 3”补款。每场创建前由 Treasury owner/多签/平台金库服务 `withdraw` 1 RTM 到新 W；成功攻破时 Arena 补铸 1 RTM 回 Treasury；未攻破退役时 W 余额退回 Treasury。外部矿工攻破时平台仍收取 0.005 RTM/条消息费，扣除推理/RSI 成本后才是平台净收入；平台自挖则平台净增 +1 RTM。
- **直观数字例子（次数驱动，不是 24h 累积）**：
  - 24 小时内 0 次成功攻破 → 新增 0 RTM；
  - 24 小时内 3 次成功攻破 → 新增 3 RTM；
  - 1 小时内连续 10 次成功攻破 → 新增 10 RTM；
  - 30 天没有成功攻破 → 新增 0 RTM。

  这不是把"1.5–2 RTM/2h"换个写法：公式里没有时间项，只有"成功攻破次数"。
- **矿工收入例子**：某矿工发 100 条消息，成本 100 × 0.005 = 0.5 RTM，加模型推理费；若成功攻破，固定拿 W 的 1 RTM。若未攻破，损失 0.5 RTM + 推理费，没有质押可退。
- **退出机制**：若平台停止运营，停止开新挖矿赛即可；已预打款到 W 的资金按 `retireMining` 退回 Treasury，不铸造，没有增发，也没有归零开关。

### 6.3 创世分配

- 平台金库保留少量创世 RTM，**唯一用途**是在 Base 的 Uniswap V2 上为 wRTM/USDC 池播种流动性（让矿工挖到的币有去处），不用于团队抛售；**挖矿 3 RTM 工作资金不从该流动性桶支出**（见下）；
- 无私募、无预挖给个人。
- 测试网 tRTM 由 `mintForTest` 注水：Faucet 领取额度 + Treasury 3 RTM 工作资金（不额外 mint 1M 给 Treasury）。`approveSpender` 只是权限、不是独立资金；`refundUnserved` 从同一 Treasury 余额扣且仅用已收手续费，默认授权 0、按需提高。主网 `testnet=false` 无 `mintForTest` 路径。
- **主网 3 RTM 工作资金来源**：来自平台运营资金/自有 RTM 份额或早期手续费积累，**不新增创世流动性桶、不从 Uniswap 流动性池直接取、不通过 `mintForTest`**。若创世分配没有运营份额，平台必须先从市场/自有份额取得 3 RTM；未到位时不能创建挖矿赛。

## 七、购买与兑换（主网）

用户想买 RTM / 矿工想换成主流币：

```
本链 RTM ──lock──▶ RTMBridge ──中继(M-of-N签名)──▶ Base 上 mint wRTM
Base 上 wRTM ──Uniswap V2──▶ USDC / ETH
反向：Base burn wRTM ──中继──▶ 本链 unlock RTM
```

- 桥有日限额与紧急暂停开关，中继签名者多签（M-of-N），异常自动停机；
- 兑换不依赖平台定价——价格完全由 Uniswap 池内市场决定，平台只提供初始流动性；
- 该模块独立于发币逻辑，feature flag 控制（法律审查通过前不启用；虚拟货币兑换业务在部分司法辖区受限，需正式法律意见，本设计不构成合规保证）。

## 八、参数一览

| 参数 | 默认值 | 谁能改 | 说明 |
|---|---|---|---|
| E（普通赛罚款时钟） | 2 小时 | 治理 | 仅用户攻防层；挖矿层无时钟 |
| 罚款率 | 25%/epoch | 治理 | 仅普通赛；24h 后攻方剩约 3.2% |
| 普通赛消息手续费 | 0.5% × S | 治理 | 进 Treasury |
| 挖矿消息手续费 | 0.005 RTM/条（0.5% × 1 RTM） | 合约常量 | 进 Treasury；矿工无质押 |
| MINING_REWARD | 1 RTM/次成功攻破 | 合约常量 | 平台逐场从 Treasury 预打款 1 RTM 到新 W；攻破补铸，未攻破退回；Treasury 工作资金共 3 RTM（含活跃 W 预打款） |
| refundAllowance | 默认 0，按已收手续费提高 | owner | **只是权限、不是独立资金**；`refundUnserved` 从同一 Treasury 余额扣，仅用已收手续费 |
| treasuryMiningFund | 3 RTM | 平台运营资金/自有份额 | `Treasury 工作资金余额 + Σ活跃 W 预打款 = 3 RTM`；3 场活跃时 Treasury 余额可为 0 |
| r（普通攻方质押比例） | 10% | 每场守方在 [2%,20%] 自选 | 仅用户攻防层 |
| 挖矿赛并发上限 K | 3 | 合约常量 | 最多 3 场活跃；攻破/退役释放 |
| defenseHash 退役 | 永久 | 合约 | 同一 hash 不能开第二场；无冷却期 |

| 数据售价 | dataPriceBps×S / attackerDataPrice | owner | 仅普通赛守方购买 |

所有参数集中在一处合约常量/治理接口，链上透明可查，改动留事件痕迹。**不存在挖矿发行速率参数。**

## 九、与既有研究的关系

- 挖矿赛就是 REDTEAM 主线（支付智能体安全评测）的**持续在线版**：原来一次性的攻防实验（L0/L1 协议）变成 7×24 的公开擂台；
- 矿工数据**无条件**经匿名化与有界化处理后进入 RSI 修复闭环，与现有 `campaign_repair`/`role_memory` 工具链无缝衔接；矿工数据仅用于 RSI，不对外出售；
- 普通攻方的数据只有在 join 时 `dataConsent=true` 才持久化并可经数据市场由守方购买；`false` 不落盘、不可售；
- 排行榜上的"攻破率走势"同时是**平台安全能力的公开审计指标**——防御有没有真变强，链上数据说话，不靠自宣。
