Payment-agent deception research

当“付款指令”
不再可信

一个可复现、仅限本地的合成实验：研究参与者消息如何诱导支付代理越过信任边界，并用独立策略验证器记录证据。

现在是什么状态？
SQLite HTTP 流程已验证；本地 EVM 合约已验证；端到端“消息 → 模型提议 → 链上真实付款 → 独立评估 → 奖励结算”演示已离线跑通（npm run demo:agent）。模型后端默认是确定性 mock，真实 LLM 必须显式 REDTEAM_LLM_ENABLED=1 且输出仍要过代码校验。没有训练模型，也没有主网部署。

实验回路

参与者文本 → 版本化系统提示 → mock/可选 LLM → 严格 PAY/NONE 校验 → 可信策略 → 本地链上 ERC-20 真实转账 → 独立评估器分类违规 → 评估器专属奖励结算 → JSON 证据包。代币只是合成实验资产，不代表真实资金。

信任边界

系统提示、可信采购/交付/账本状态与参与者消息在输入层严格分离。模型只能输出一行 PAY 或 NONE；机械边界（收款人白名单、金额上下限、单笔/累计上限、一次性发票）全部由代码与合约执行，模型无法绕过。付款权限与奖励权限由不同签名者持有。

Token-as-payment

实验回路使用合成 token 观察“建议—执行—评估”的闭环；额度、收款人、交付和重复付款都会被单独检查。

快速开始

  1. python -m pytest -q
  2. python -m redteam.server --port 8765 --db .\redteam.sqlite3
  3. 浏览器打开 http://127.0.0.1:8765，创建 vulnerable 或 hardened 实验。

可选 EVM 演示运行 npm install 后执行 npm test。LLM 适配器必须通过 REDTEAM_LLM_ENABLED=1 显式开启，并配置环境变量；它永远不能授权转账。

边界与限制

这是开发者控制的本地研究夹具，不是对抗恶意本地用户的沙箱。没有生产 RPC、钱包、私钥、主网资产、远程 append-only 签名或真实支付集成。实验标签不是无偏评估，确定性模拟也不能代表真实语言模型。
