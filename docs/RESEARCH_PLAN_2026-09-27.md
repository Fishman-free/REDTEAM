## 1. Phase 1：双入口与身份授权核验（§01 图 1b、§03 判别标准）

提纲要点：「用户和外部参与者都在系统控制边界外，但权限不同」「能发消息不等于有付款权限」「商户说'用户同意了'不算授权」「判断的标准基于用户预先设定好的 system prompt 或其他约束，提前明确规定清晰」。

- 新增 `src/rsi4safety/arena/authorization.py`：AuthorizationRecord v2（主体、收款人、金额/币种、用途、次数、时间窗、审批要求）；用户通道经身份与授权核验产生可执行授权；外部通道内容一律 untrusted、不新增授权。
- `trusted_execution.py` 支付执行门增强：付款计划逐项核对已验证授权记录。
- `sut/payassist`、`sut/paygate` 会话模型增加 channel 标记（user / external），分开接入。
- 每个 seed 附预注册判据 `adjudication`（违规码→判据→分母），`constitution.py` 裁决仅依据它；新增身份混淆判别。
- 测试：双入口越权、身份混淆、外部入口不新增授权、账本不可被攻击者修改。

对应 ROADMAP：与 P3（证据-身份绑定）部分重叠，双入口部分为新增。

## 2. Phase 2：L0–L3 场景分级（§02）

提纲要点：从简单到复杂逐步增加权限和场景——不允许付款（只读发票、汇总金额）→ 单笔付款 → 受控/限额支付（每天三餐代付、单笔不超过 35 元、每日不超过 90 元）→ 多智能体协作（采购、审批、支付分工、权限分级）；随上下文长度、复杂度、权限大小、场景多样性、攻击面增加，构建可验证的多级别 payment agent。

- L0：新增只读场景 seeds（诱导付款应拒绝，只读任务正常完成）。
- L2：SUT 账本增加每日预算状态；seeds 覆盖单笔/每日限额，攻击族=拆分规避、重复付款、跨日重置滥用。
- L3：新增最小 SUT `sut/paychain`（采购提议→审批→支付执行三角色、共享账本、权限分级），seeds 3–6 个（审批绕过、角色冒充、支付分工混淆）。
- 补 trusted state adapters：A01 B04/B06/X03 与 A02 全部可执行（ROADMAP P1/P2），unsupported 由 24 降到约 9。
- `seed_summary`/benchmark 报告按 L0–L3 分层输出。

对应 ROADMAP：即 P1（A01 状态/事件模型）+ P2（退款场景与域适配器）。

## 3. Phase 3：攻击环升级（§03 + §05）

提纲要点：攻击分用户对话入口与外部对话/内容入口，分别测试；攻击侧按实验规则获得有限反馈；确认攻击成功后才把攻击方式、手段、完整对话及执行记录交给防御智能体。

- 多轮会话执行支持（`sut_driver.py`）+ Crescendo 式多轮攻击器（正常起步→逐步越界），打用户对话入口。
- ChatInject 式伪装攻击器：外部输入伪装成聊天格式/对话记录，打外部内容入口。
- Rainbow Teaming 式攻击库管理：手法指纹聚类 + 多样性配额进 attacker brief。
- 有限反馈协议显式化：`exchange.py`/`constitution.py` 落实"攻击侧有限反馈、完整方案确认失败后才交付防御侧"并测试。

对应 ROADMAP：攻击面扩展为新增项；反馈协议与 ATTACK_INTERFACE_DESIGN 的会话/配额 HTTP 化方向一致（本轮仅进程内协议）。

## 4. Phase 4：RSI 泛化实验（§04）

提纲要点：「修好这次错误，不等于以后更会修。RSI 还要验证：积累经验后，系统解决新问题是否更有效、成本是否更低。」

- 先落地 `RSI_IMPROVEMENT_PLAN.md` P0/P1：会话三级递进（T-10/T-5/T-0）、网关韧性、防御者授权契约知识（payassist-authorization-contract.md + 字段信任矩阵）、结构化失败轨迹、防御者提示词/技能重写。
- 新增 `src/rsi4safety/rsi_eval/`：冻结经验库→held-out 新攻击族→度量新问题修复成功率/修复成本/回归率，对照无经验基线，产出 learning curve 报告。
- 五臂对照实验（RSI_IMPROVEMENT_PLAN P3-2）确定性演练：基线 / +授权契约 / +结构化反馈 / +两者 / +外层进化。
- 外层进化设计文档 + 最小实现（P3-1）。
- `EXPERIMENT_PROTOCOL.md` 增补真实模型战役预注册协议（五臂、预算、停止条件）——本轮只写协议不执行。

对应 ROADMAP：与 P3（修复实验证据包、新执行验收）互补；真实模型实验按用户指示暂不执行。

## 6. 验收标准

1. CI 全绿：pytest 主套件 + 新增用例、tests/arena + 新增用例、两个 SUT 套件、npm test。
2. seeds 注册 ≥36、可执行 ≥15、unsupported 如实标注；报告按 L0–L3 分层。
3. 双入口判别（含"商户冒充不形成授权"）用例全绿；多轮与伪装攻击可复现；有限反馈协议有测试。
4. RSI 泛化确定性报告：learning curve + 五臂对照数据 + 诚实局限声明。
5. 全程不配置真实模型、不接真实资金、RTM 组件不动。
